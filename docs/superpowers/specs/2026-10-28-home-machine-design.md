# 首页只讲机器本身 — 设计

- 日期：2026-10-28
- 范围：macOS 的「系统状态」页，也就是首页。Windows 首页不改。
- 草图：`.superpowers/brainstorm/36592-1793158059/content/home-machine-v2.html`（不进仓库）。维护者看了草图，回复「好的」。

## 一、为什么

有了「进程」页之后，首页的「占用最多的应用」列表就重复了。维护者的原话：

- 「既然我们把进程单列出来了，首屏再放应用列表就重复了，应该看看怎么再优化下首页」
- 「首页只讲机器本身，可以看看能不能把更多的关于机器的信息放到首页」

所以首页的定位改成：这台 Mac 是什么、现在状态怎么样。「谁在占」交给「进程」页。

## 二、目标、非目标

**目标**

- macOS 首页不再列出 App，改为显示这台 Mac 的身份、健康状况和各个部件的实时状态。
- 把以前没有的机器信息放上首页：
  - 散热状态、芯片温度、风扇转速、整机功耗；
  - GPU、网络速度；
  - 磁盘的读写速度、型号、健康、寿命已用、累计写入量和温度；
  - 电池温度和所接电源的功率；
  - CPU 性能核、能效核各自的使用率。
- 首页的开销比现在更小：不再每 2 秒读一遍全部进程和 NSWorkspace 的 App 列表。

**非目标**

- 首页不出现 App 列表。提示条照旧（见第三节第 3 条）。
- Windows 首页这一版不改，应用列表保留。Windows 没有「进程」页，那是它唯一能看「谁在占」的地方。
- 这一版不读：
  - CPU 和 GPU 各自的功耗和频率：要用更底层的接口，这一版先不做；
  - Wi-Fi 名称：需要定位权限；
  - 序列号：隐私。
- 不在后台采样，也不存历史：和现在一样，只在首页显示时采样。

**做了也算失败**

- 首页比现在更耗电，或者更卡。
- 某台 Mac 读不到某一项时，出现空白、0、「NaN」或者报错。例如 MacBook Air 没有风扇，Mac mini 没有电池，或者型号不在型号表里。

## 三、页面（macOS）

从上到下：

1. **机器身份**
   - 大标题是型号全名，如「MacBook Pro 16 英寸 · 2023」。型号表里查不到时，显示系统给的型号名加型号标识，如「MacBook Pro（Mac14,10）」。
   - 第一行规格：芯片 · CPU 核数（性能 + 能效）· GPU 核数 · 内存 · 磁盘容量。
   - 第二行：macOS 版本 · 已运行时长 · 显示器。每台显示器写名字、分辨率和刷新率。
2. **健康条**，四格：
   - 散热状态：系统的 thermal state，分「正常 / 偏热 / 很热 / 过热」；
   - 芯片温度；
   - 风扇：每个风扇的转速，没有风扇时写「无风扇」；
   - 整机功耗（W）。
3. **提示条**：现有的几条都保留，包括内存紧张、交换文件、磁盘不足、崩溃转储、增长提醒。
   - 内存提示的按钮改为打开「进程」页的内存标签。原来是滚动到应用列表。
   - 崩溃转储和增长提醒会点名 App。它们是「需要你处理的事」，不是列表，所以照旧。
4. **六张卡**：
   - **CPU**：使用率、三个负载值、现有的 1 分钟曲线。新增性能核、能效核各自的使用率。
   - **GPU（新）**：使用率、核数、占用的内存，加一条小曲线。
   - **内存**：和现在一样。
   - **磁盘**：
     - 现有：可用和总量、「清理」按钮；
     - 新增：SSD 型号、健康（NVMe 的严重警告为零写「正常」，否则写哪一项出了问题）、寿命已用（这台 26%）、累计写入量（这台 624 TB）、磁盘温度、读写速度。
   - **网络（新）**：
     - 当前的下载和上传速度，加一条小曲线；
     - 连接类型：Wi-Fi 或以太网，不显示 Wi-Fi 名称。
   - **电池**：
     - 现有：电量、健康、循环次数、状态；
     - 新增：电池温度、所接电源的功率（W）；
     - 没有电池的 Mac 不显示这张卡，和现在一样。
5. **去掉**「占用最多的应用」整张卡，连同其中的按内存/按 CPU 切换、退出按钮和「查看全部」。要看谁在占，走侧栏的「进程」，或者点内存提示条上的按钮。
6. **样式**：沿用现在的卡片、数字过渡和曲线的做法，布局见草图 v2。

## 四、数据

下面各项都不需要管理员权限，2026-10-28 在维护者的 MacBook Pro（M2 Pro，macOS 26.6.2）上逐项读过。

| 项 | 来源 | 何时读 |
|---|---|---|
| 型号全名 | IORegistry 设备树根节点的 `product-name`（这台：`MacBook Pro (16-inch, 2023)`）。中文显示时把「(16-inch, 2023)」写成「16 英寸 · 2023」。读不到时用 `hw.model`。系统自带的 `SIMachineAttributes.plist` 太旧，里面没有 Mac14,10，不用 | 进入首页时读一次 |
| 性能核、能效核数 | `sysctl hw.perflevel0/1.name`、`.physicalcpu`（这台：8 性能 + 4 能效） | 一次 |
| GPU 核数 | IORegistry `AGXAccelerator` 的 `gpu-core-count`（这台 19） | 一次 |
| 显示器 | CoreGraphics 的活动显示器列表和当前模式，加 NSScreen 的名字 | 进入首页时一次，显示器变化时再读 |
| 散热状态 | `NSProcessInfo.thermalState` | 每 2 秒 |
| 芯片温度 | IOHID 温度传感器（私有 API `IOHIDEventSystemClient`，PrimaryUsagePage 0xff00、PrimaryUsage 5，事件类型 15）。取名字含 `tdie` 的 SoC 传感器中的最大值。这台读到 63 个传感器，die 最高 51.9 °C | 每 2 秒 |
| 风扇、整机功耗 | AppleSMC 用户客户端，`IOConnectCallStructMethod` 选择子 2，参数结构 80 字节。键 `FNum`（风扇个数）、`F<i>Ac`（float，rpm）、`PSTR`（float，W）。这台：2 个风扇 1333 / 1464 rpm，37.8 W | 每 2 秒 |
| GPU 使用率、内存 | IORegistry `IOAccelerator` 的 `PerformanceStatistics`：`Device Utilization %`、`In use system memory`。这台：8%、1.1 GB | 每 2 秒 |
| 性能核 / 能效核使用率 | `host_processor_info` 每个逻辑核的 ticks 差值。核的类型按 IORegistry 里每个 cpu 节点的 cluster-type 判断，不要假设编号顺序 | 每 2 秒 |
| 磁盘读写速度 | IORegistry `IOBlockStorageDriver` 的 `Statistics`（`Bytes (Read)` / `Bytes (Write)`）的差值。这台：10.3 / 9.6 MB/s | 每 2 秒 |
| SSD 型号 | IORegistry 里 NVMe 设备的型号属性（这台：APPLE SSD AP0512Z） | 一次 |
| SSD 健康、寿命已用、累计写入、温度 | macOS 自带的 NVMe SMART 插件：在 IORegistry 里找带 `NVMe SMART Capable` 的服务（这台是 `IOEmbeddedNVMeBlockDevice`），`IOCreatePlugInInterfaceForService` 取 `kIONVMeSMARTUserClientTypeID`（AA0FA6F9-C2D6-457F-B10B-59A13253292F），再 QueryInterface 取 `kIONVMeSMARTInterfaceID`（CCD1DB19-FD9A-4DAF-BF95-12454B230AB6），调 `SMARTReadData` 读 512 字节的 SMART 日志：第 0 字节严重警告、1–2 温度（K）、3 可用备用、5 寿命已用（%）、48 起是写入的数据单位（每单位 512 000 字节）。2026-10-28 用普通账户（uid 501，不 sudo）读到：警告 0、32 °C、备用 100%、已用 26%、写入 624.4 TB | 健康和寿命一次（进入首页时）；温度每 2 秒用 IOHID 传感器 `NAND CH0 temp` 读，不必每次走插件 |
| 网络速度 | 64 位的接口计数（sysctl `NET_RT_IFLIST2` 的 `if_data64`）的差值。`getifaddrs` 给的是 32 位计数，4 GB 就会回绕，不能用 | 每 2 秒 |
| 连接类型 | 当前活跃的接口是 Wi-Fi 还是以太网 | 每 2 秒或网络变化时 |
| 电池温度、电源功率 | IORegistry `AppleSmartBattery`：`Temperature`（单位 0.01 °C）、`AdapterDetails.Watts`。这台：30.7 °C、90 W | 和现在的电池读数一起，每分钟 |

## 五、开销

- 首页只在显示时采样，这一点不变。
- macOS 首页不再读进程列表和 NSWorkspace。对进程页的剖析显示，NSWorkspace 每 2 秒读一次，单这一项就占一个核的约 1.3%。现在的首页为了「占用最多的应用」也是每 2 秒读一次，去掉列表就省掉了。
- 新增的读数每 2 秒一次，合计目标是几毫秒。全部来自 IOKit、sysctl 和 IOHID，不启动任何子进程。
- **上限**：首页显示时，Cleanzo 主进程加子进程不超过一个核的 1%，网页进程不超过 1.5%。
- **量法**：首页和一个静态页面（例如「设置」）每 30 秒交替，各量 3 轮取差值，和进程页的量法相同。要避开刚启动时的磁盘统计，打字时输入法造成的干扰也要用交替量的差值排除。

## 六、验收

1. 在维护者的 Mac 上，草图里的每一项都有真实读数，并且和系统自己的数对得上：
   - 活动监视器：CPU、GPU、内存、网络、磁盘；
   - 系统信息：型号、核数、SSD、显示器；
   - `ioreg`：电池；
   - 风扇：Apple 芯片的 `ioreg` 里没有风扇数据。用负载让风扇转起来，看数值跟着升、空闲后回落；能用 sudo 时再和 `powermetrics` 对照；
   - SSD：和 smartmontools 的 `smartctl -a disk0`（如已安装）或系统信息里的型号对照。
2. 读不到的项不出现空白、0 或错误，而是省掉或者写「—」，具体由实现决定。在维护者的 Mac 上用假数据源覆盖以下情况：
   - 没有风扇；
   - 没有电池；
   - 读不到温度或功耗；
   - 型号不在型号表里。
3. Windows 首页和现在一样，包括应用列表。
4. 内存提示条的按钮打开「进程」页的内存标签。
5. 冒烟巡检：首页的明暗两张截图正常，`errors.json` 为空。
6. 开销达到第五节的上限。

## 七、留给实现决定

- 每一项读不到时，是省掉还是写「—」。
- 曲线的点数和颜色，GPU 和网络要不要和 CPU 一样用 1 分钟。
- 健康条四格的文案。thermal state 四档对应「正常 / 偏热 / 很热 / 过热」只是 Claude 的初稿。
- 卡片怎么排，窗口窄时怎么折行。
- 新数据放进现在的 `StatusSample`，还是另开一个流。
- 私有 API（IOHID 温度）和 SMC 读不到时的降级办法。
- **实现时的决定（2026-10-29）**：首页的数字滚动即使限到每秒 15 次，网页进程也要多花约 0.6% 个核，超出第五节的上限。维护者选了 macOS 首页的大数字直接换成新值；曲线平移和条的过渡保留（已改成交给合成器，几乎不花 CPU）。Windows 首页照旧滚动。

## 八、Claude 替维护者定的（审阅时请重点看）

- **芯片温度**取 SoC die 传感器里的最高值，意思是「芯片现在最热的地方有多热」，不取平均。
- **网络**只显示当前速度，不显示累计流量，也不显示 Wi-Fi 名称。
- **SSD** 显示健康、寿命已用和累计写入。起初以为这些要管理员权限，第三方审阅指出 macOS 自带的 NVMe SMART 插件不需要，2026-10-28 实测确实普通账户就能读，所以加上。
- **提示条**原样保留，包括会点名 App 的崩溃转储和增长提醒。
- **Windows 首页**暂不改。
- **型号全名**直接读 IORegistry 的 `product-name`，不维护型号表（第三方审阅发现的）。
