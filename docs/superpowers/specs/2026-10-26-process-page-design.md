# Cleanzo 进程页 · 设计

- 日期：2026-10-26
- 状态：待维护者审阅
- 目标版本：和占用增长一起发，不单独发
- 平台：这一版只做 macOS。Windows 维持现状，见第八节。
- 关系：建立在《Cleanzo 占用增长监控 · 设计》（`2026-10-24-growth-monitor-design.md`）之上。
  - 占用增长的量法、记录、提醒、通知、菜单栏和常驻都不变。
  - 本设计取代它第六节里「新页面『占用增长』」的位置和入口。

## 一、为什么

- **「占用增长」单独一页不合适。** 占用增长做完后，维护者在 Cleanzo Dev 里看了一遍，觉得它单独成页「不伦不类」：
  - 打开是空的，量一次要 3～4 分钟，第二天才看得到增长；
  - 看起来像一个慢一点的「空间分析」。
- **维护者的想法：** 做一个类似活动监视器的进程监控，把占用增长的报警放在里面。
- **什么时候会看：** 维护者说「电脑卡了，才去看」。所以这一页最要紧的是：打开的第一眼就能看到是谁在拖慢。
- **系统状态页现在看不到系统进程。**
  - 「系统状态」页已经有一张「占用最多的应用」：可以按内存或按 CPU 排，同一个 App 的进程合成一行，能退出。
  - 但它只统计你账户下的进程。
  - 维护者参考的第三方监视器截图里，排在前面的系统进程加起来超过一整个核：WindowServer 40%、ecosystemanalyticsd 14%、trustd 13%、ecosystemd 10%……这些系统状态页一个都看不到。

## 二、目标与不做

**目标**

1. 新页面「进程」，顶上三个标签：CPU、内存、磁盘占用。
2. **CPU、内存两个标签**：实时列出进程。
   - 同一个 App 的进程合成一行，点开能看到里面的各个进程。
   - 系统和其他账户的进程也列出来，用估算值。
3. **一打开就看得出卡在哪。**
   - 默认按 CPU 从高到低排。
   - 整机内存紧张或 CPU 很忙时，顶上一句话说清楚，并点名占得最多的 App。
4. **找到之后能处理**：先正常退出；退不掉时可以强制退出，要确认。
   - 强制退出是维护者 2026-10-26 定的：「提供强制退出」。
5. **磁盘占用标签**：把现在的占用增长列表整个搬进来。
   - 有增长提醒时，标签上显示数字。
   - 涨过提醒线的 App，在 CPU、内存标签里也挂一个小标签。
6. **「暂停 / 继续」开关**：页面上有一个，默认在走。

**这一版不做**

- 不在后台统计进程，不保存进程历史，不做 CPU 或内存的报警和通知。
- 不加 GPU、能耗、线程、网络、磁盘读写这些列。
- 不结束系统进程，不结束其他账户的进程，也不结束单个子进程。退出和强制退出只给你账户下、有 Dock 图标的 App。
- 菜单栏不显示实时的 CPU 和内存。
- 不做 Windows。

**绝对不要**

- Cleanzo 自己让本来就卡的电脑更卡。页面不显示时不统计；显示时开销要小，具体数字见第六节。
- 照搬维护者给的参考截图。它的布局、侧栏分区、筛选条和那一排列都不照做，用 Cleanzo 自己的样式。维护者原话：「你不能完全抄袭我给你的图」。
- 不确认就强制退出，或者给系统进程放退出按钮。

## 三、页面

**位置和样式**

- **位置**：
  - 侧栏里，「进程」放在「系统状态」下面。
  - 「空间」分组里的「占用增长」去掉。它在 Windows 上本来就隐藏。
- **页头**：
  - 标题「进程」，副标题「按 App 看谁在占 CPU、内存和磁盘」。
  - 右边是三个标签的分段切换，样式和系统状态里「按内存 / 按 CPU」的那个一样。
- **样式**：沿用系统状态「占用最多的应用」那一套：白底卡片、字母头像、「N 个进程」、平时不显眼的「退出」按钮。

### CPU 标签和内存标签

**列表**

- **列**：应用、CPU、内存、操作。
  - CPU 标签按 CPU 排，内存标签按内存排。
  - 点列头可以换排序。
- **一行一个 App**：同一个 App 的进程合成一行，写「N 个进程」。合并规则沿用系统状态现在的（`monitor.go` 的 `mergeApps`），另外两条：
  - 其他账户的进程，如果可执行文件在某个 `.app` 里，也算到这个 App 头上，比如 Microsoft Defender 的 root 后台进程。
  - 其余的系统进程和其他账户的进程，每个单独一行，名字旁边标「系统」。
  - 命令行程序单独成行：不在任何 `.app` 里的程序，比如 node、python、cargo、claude、zsh，按程序名合成一行，不算到启动它的终端或 IDE 头上。系统框架里替某个 App 干活的进程，比如 WebKit 的网页进程，仍然算到那个 App 头上。
- **点开一行**：
  - 列出里面的进程，各自显示 CPU 和内存。
  - 同名的合成一条，写「× N」，比如「Google Chrome Helper (Renderer) × 61」。
- **估算值**：
  - 其他账户的进程，数字前面带「≈」，颜色淡一些。
  - 一个 App 里只要有估算的进程，这一行的合计也带「≈」。
- **页脚**：一行字，说明「系统」和「≈」的意思，以及 CPU 按单核算，可以超过 100%。
- **什么时候冻结顺序**：只在确认框开着、或者正在退出某个 App 的时候冻结。这时哪些行、行的顺序都不变，数字照常更新。
  - 和系统状态不同，鼠标停在列表上不冻结。这一页整页都是列表，鼠标几乎总在上面，冻结会让刚冒出来的大户排不上来。
  - 想停下来慢慢看，用「暂停」。

**顶上的诊断条**（只在有问题时出现）

- **内存紧张**：
  - 判断标准沿用系统状态现在的，即内存压力达到警告或严重。
  - 文案：「内存不够用了：系统正在压缩内存、写交换文件，所以会卡。占得最多的是 X（31.5 GB）」。
  - 点「看内存」切到内存标签。
- **CPU 很忙**：
  - 判断标准：整机 CPU 连续 3 次统计（大约 6 秒）都在 80% 以上。
  - 文案：「CPU 很忙，占得最多的是 X（53.8%）」。
  - 点「看 CPU」切到 CPU 标签。
- 两种情况都有时，只写内存那条。

**退出**

- **谁有按钮**：只有你账户下、有 Dock 图标的 App，和系统状态现在一样。按钮平时不显眼，鼠标移上去才明显。
- **正常退出**：
  - 点「退出」先弹确认框，写明是哪个 App，和系统状态现在一样。列表在跳也不会点错。
  - 确认后正常退出，和在 Dock 里选「退出」一样，没保存的内容 App 会先问你。
- **强制退出**：
  - 点了「退出」5 秒后还在运行，这一行写「还没退出」，按钮变成「强制退出」。
  - 点「强制退出」会弹确认框：「强制退出『X』？它没有响应正常退出。强制退出会立刻关掉它，没保存的内容会丢失。」
  - 确认后才关。
- **没有按钮的**：系统进程、其他账户的进程、展开后的单个进程。

**暂停 / 继续**

- **位置**：在 CPU、内存标签的页头右侧。
- **默认**：在走，每 2 秒刷新一次，和系统状态现在一样。
- **点「暂停」**：
  - 不再统计，列表停在那一刻，不再跳动，方便看清楚、点退出。
  - 页面上写一个淡淡的「已暂停」。
- **点「继续」**：接着统计。
- **每次进入这一页**：都是在走的状态。你通常是卡了才来，要看的是现在。
- **离开这一页**：切到别的页面、关掉或隐藏窗口，统计就停，不管开关是什么状态。

**刚打开时**

- 内存马上有数字。
- CPU 要隔一会儿统计两次才算得出来，所以第一次的间隔缩短到大约 1 秒。

**跨标签的小标签**

- **哪些 App 挂**：近 7 天触发过增长提醒、又没被忽略的 App。口径和状态页那条增长提示一样。
- **挂在哪**：CPU、内存标签里这个 App 的那一行，写「磁盘 7 天 +X GB」。
- **点一下**：切到磁盘占用标签，并定位到它。

### 磁盘占用标签

- **内容**：就是现在「占用增长」页的全部：
  - 请你打开后台监控的提示，或者关掉之后的那一行提示；
  - 上次和下次量的时间、「现在量一次」；
  - 没有完全磁盘访问权限时的说明；
  - 空状态、只有一次记录时的说明；
  - 列表、展开后的目录，以及各种操作。
- **「现在量一次」的位置**：
  - 原来在页头，现在挪到这个标签里状态那一行的右边。
  - 没有记录时，只在空状态里放一个，沿用 f9f628d 的做法。
- **标签上的数字**：有增长提醒的 App 数，口径和状态页那条增长提示一样。
- **没有「暂停 / 继续」**：这个标签不用它。
- **入口**：原来所有打开「占用增长」页的地方，都改成打开「进程」页的磁盘占用标签，并定位到那一行：
  - 通知；
  - 菜单栏里涨得最多的 3 个 App；
  - 状态页的增长提示。

### 系统状态页

- 「占用最多的应用」保留不变，标题行加一个「查看全部」，跳到进程页。当前按什么排，就打开 CPU 或内存标签。
- 这里的退出照旧，不加强制退出。要强制退出，去进程页。
- 增长提示照旧，点了跳到进程页的磁盘占用标签。

## 四、数据从哪来

下面几条在维护者的 Mac 上试过：macOS 26.6，没有管理员权限。

- **你账户下的进程**：`proc_pidinfo` 和 `proc_pid_rusage` 都能读，CPU 时间和内存都是精确的。系统状态现在就是这么读的。
- **其他账户的进程**（root、_windowserver 等）：
  - 这两个调用都被拒绝，返回 EPERM。
  - 系统自带的 `/bin/ps` 带 root 权限（setuid root），能给出每个进程的 CPU 百分比、常驻内存（RSS）和 CPU 时间。「≈」的数字就从这里来。
  - `ps` 的 CPU 百分比是系统算的衰减平均，内存是 RSS，和活动监视器的「内存」口径不一样，所以叫估算。
  - 只在页面显示、开关在走的时候调用 `ps`。
  - `ps` 每调用一次大约花 70 毫秒 CPU（审阅时在维护者的 Mac 上量的，大约 1300 个进程），所以不跟着每 2 秒调用，而是大约每 6 秒一次。「≈」的数字也就大约 6 秒更新一次；你账户下的进程照常每 2 秒更新。
- **每个进程各自读写了多少磁盘**：没有管理员权限读不到。
  - `ps` 的读写两列是空的，`top` 只有整机合计。
  - 所以磁盘占用的报警仍然靠量目录大小，也就是占用增长现在的做法。

## 五、和占用增长的关系

- **不变的**：量法、记录、增长和提醒的算法、通知、菜单栏、常驻和开机启动，以及设置页里的那一节。
- **变的只有界面位置**：「占用增长」页变成「进程」页的一个标签，所有入口都改指向这个标签。
- **被取代的两条**：
  - 占用增长设计第九节里「页面叫『占用增长』，放在『空间分析』后面」，由本设计取代。
  - 2026-10-15 系统状态设计里「不提供强制退出」，在进程页由本设计取代；系统状态页本身仍然不提供。

## 六、验收

1. **CPU 排序**：在终端里开一个持续占 CPU 的命令行进程，比如 `yes > /dev/null`，再打开进程页。2 秒内它以自己的名字排在 CPU 标签第一，而不是算到终端头上。
2. **系统进程**：WindowServer 这类系统进程出现在表里，标「系统」，数字带「≈」，没有任何按钮。
3. **暂停和继续**：
   - 点「暂停」后，列表不再变化，也不再读进程。测试里要能看出没有新的读取。
   - 点「继续」后恢复统计。
   - 离开页面再回来，是在走的状态。
4. **离开即停**：切到别的页面或者关掉窗口后，不再读进程，也不再调用 `ps`。
5. **退出和强制退出**：用一个有未保存内容的测试 App。
   - 点「退出」，它先问你。
   - 5 秒后还没退，出现「强制退出」。
   - 在确认框里点取消，什么也不发生；点确认，它被关掉。
   - 系统进程和展开后的单个进程没有任何按钮。
6. **诊断条**：
   - 模拟内存紧张：显示内存那条，点名占内存最多的 App。
   - 模拟整机 CPU 连续 3 次都在 80% 以上：显示 CPU 那条。
   - 两种情况同时满足：只显示内存那条。
7. **磁盘占用标签**：
   - 占用增长设计第七节的验收全部照旧通过。
   - 从通知、菜单栏、状态页进来，都打开这个标签并定位到那一行。
   - 标签上的数字，和状态页增长提示里的 App 数一致。
8. **侧栏**：
   - 「进程」在「系统状态」下面，没有「占用增长」。
   - Windows 上看不到「进程」，系统状态页和现在一样。
9. **开销**：在维护者的 Mac 上（大约 1300 个进程），进程页开着、在走的时候，取一分钟的平均：
   - Cleanzo 主进程加上它调用的 `ps`，合计不超过一个核的 3%。按主进程自己和它的子进程一共用掉的 CPU 时间算（getrusage 的 SELF 加 CHILDREN）。
   - Cleanzo 的网页进程（WebKit）另算，也不超过一个核的 3%，用 `top` 量。
   - 页面不显示时，不再统计，也不再调用 `ps`。

## 七、留给实现决定

- **读其他账户进程**：具体用 `ps` 还是 `top`、怎么解析、要不要每两次统计才调用一次。
- **合并、排序和「× N」**：细节由实现决定，只要满足第三节。
- **命令行程序**：怎么判断一个进程是命令行程序，还是系统框架里替 App 干活的 XPC 服务。
- **诊断条**：文案，以及 80%、6 秒这两个数在合理范围内微调。
- **跨标签的小标签**：怎么把占用增长里的 App 和进程这边的 App 对上，用 bundle ID 还是路径。
- **动效、骨架、空状态**：尽量复用系统状态和占用增长现有的部件。
- **文案**：中英文的细节。

## 八、Claude 替维护者定的（审阅时请重点看）

- **只在这一页显示时统计**，不在后台统计，不存历史。维护者说：「你觉得最合理是哪个，你就用哪个」。
  - 理由：你是卡了才来看，这时候拖慢的那个通常还在跑。
  - 一直在后台统计会一直耗电，换来的只是少数情况下能看到「刚才是谁」。以后需要可以再加。
- **「暂停 / 继续」**：每次进入页面都重置为在走。
- **系统进程和其他账户的进程**：列出来，用估算值，不给任何操作。
- **强制退出的保护**（做不做是维护者定的）：
  - 只在正常退出 5 秒没成功之后出现，要确认；
  - 只给你账户下有 Dock 图标的 App；
  - 系统状态页不加，只在进程页有。
- **诊断条**：
  - 内存紧张沿用系统状态的标准；
  - CPU 是整机连续大约 6 秒都在 80% 以上；
  - 两种都有时只说内存。
- **列**：只有 CPU 和内存。
- **命令行程序单独成行**，不算到启动它的终端或 IDE 头上。审阅时有人指出：沿用系统状态的合并规则，失控的 node 会算到「终端」头上，诊断条会说「占得最多的是终端」，能点的只有退出整个终端。
- **顺序只在确认框开着和退出期间冻结**，鼠标停在列表上不冻结；想停下来看，用「暂停」。
- **`ps` 大约每 6 秒调用一次**。开销上限：主进程加 `ps` 合计 3%，网页进程另算 3%。
- **系统状态**：「占用最多的应用」保留，另加「查看全部」。
- **平台**：这一版只做 macOS。Windows 的进程页以后再做；系统状态页在 Windows 上已经能统计进程，到时可以复用。
- **发版**：和占用增长一起发，不单独发。
