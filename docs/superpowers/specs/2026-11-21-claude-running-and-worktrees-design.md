# Claude Code 页的「运行中」，和整个 agent worktree 的移除 — 设计

- 日期：2026-11-21
- 状态：已实现（2026-11-21，未发版）。实现时改掉的规则标着「实现时改」，汇总在第十四节。
- 平台：只做 macOS。Windows 上这两样都不出现，现有页面不变。
- 来由：维护者让对比 [seshka](https://github.com/jigjoy-ai/seshka)（Swift 写的菜单栏工具，MIT，macOS 14+），问有没有能集成进来的。
- 关系：改了两条旧裁定，见第十四节。
  - 进程页设计（`2026-10-26-process-page-design.md`）的「不结束单个子进程」。
  - Dev space batch（`2026-11-17-dev-space-batch-design.md`）的「Worktrees are never removed, only their build folders」。

## 一、为什么

Cleanzo 已经能看清 AI 编码工具占的磁盘。它们还留下两样东西，Cleanzo 现在看不到，也收不了：

- **占着内存的会话和进程。** 开着不用的 Claude Code 会话，和已关闭的会话留下的开发服务器、文件监视。进程页把它们按名字合成一行，看不出是哪个会话的、占着哪个端口，也没有结束按钮。Claude Code 自己的进程现在还显示成版本号（`2.1.321`），认不出来。
- **agent 在仓库里建的 worktree。** 0.6.0 只列其中闲置 14 天的构建产物，整个 worktree 不动。

seshka 专做这件事。这一批把它的归属思路用 Go 在 Cleanzo 里重做一遍，不带它的程序，规则比它收得更紧。它的缓存清理 Cleanzo 已经有了；合盖不睡要管理员密码；到点自动结束不符合「先列出、问过才动」。这三样都不做。

## 二、在维护者 Mac 上量到的（2026-11-21，只读）

| 项 | 读数 |
|---|---|
| 开着的 Claude Code 会话 | 几次读数是 8 到 9 个，只有 1 个在干活 |
| 空闲超过 2 小时的会话 | 6 个（5 个约 7 天半，1 个约 5 天），占约 1.45 GB。这是 RSS，实际占用更高 |
| 全部 Claude Code 进程 | 约 2.3 GB（RSS） |
| 已关闭会话留下的进程 | 0 个。这只是一个时间点 |
| Claude Code 建的 worktree | 1 个，1.19 GB，约 8 周没动 |
| Codex 的 worktree | 0 个（11 月 17 日有 5 个） |

设计依赖的事实：

- **标记。** Claude Code 启动的进程，环境变量里有 `CLAUDECODE=1` 和 `CLAUDE_CODE_SESSION_ID=<uuid>`。`CLAUDE_PID` 只有一部分进程带（8 个带标记的进程里 1 个），不能只靠它。
- **会话记录。** 每个 Claude Code 进程在 `~/.claude/sessions/<pid>.json` 有一份记录，文件名就是 pid。用到的字段：`sessionId`、`cwd`、`name`（会话标题）、`status`（见到 `idle` 和 `busy`）、`statusUpdatedAt`（毫秒）、`procStart`（UTC 的 `Sat Nov 14 09:12:33 2026` 这种写法）、`entrypoint`（见到 `cli` 和 `t3-code`）。这份文件没有文档，随时可能变。
- **Claude Code 进程的名字。** 内核里的短名字和可执行文件名都是版本号（`…/claude/versions/2.1.321`），`argv[0]` 的文件名才是 `claude`。所以进程页现在把它们显示成 `2.1.321`、`2.1.323`、`2.1.330` 三行。`process_darwin_test.go` 里的 `TestGroupProcessesUsesKernelNames` 假设内核短名字是 `claude`，和这台机器不符。
- **它的直接子进程分两种。** 和它同一个进程组的：7 个 `cmux-cua`、1 个 `bash`，是它自己的辅助进程。自成一组的：包命令用的 `zsh`。
- **原生读取够快。** `kern.proc.all` 列出全部 957 个进程用 0.4 毫秒；对本账户 712 个进程逐个读 `kern.procargs2`（参数和环境变量）一共 6 毫秒、724 KB。不需要调用 `ps`。
- **多数进程看不到环境变量。** 712 个里有 547 个不给：macOS 自带的程序（`zsh`、`bash`、`sleep`）和一部分 App 的辅助进程（Chrome）。所以光靠标记不够。
- **标记会被带到别处。** 从会话里启动的东西都继承标记，包括用户接着用的编辑器：这台机器上 TRAE 的命令行入口用 `open --env` 把全部环境变量交给 App。
- **Codex 没有会话标记。** 它的进程带 `CODEX_SHELL`、`CODEX_HOME` 这类变量，没有一个是会话 ID。TRAE 和 Orca 当时没在运行，没验证。
- **那个 worktree 的状态。** 没上锁；`git status` 是干净的；被忽略的内容有 `node_modules`、`dist`、`.vercel` 等；分支上有 62 个提交不在别的分支或远端上。
- **git 的行为**（Apple Git 2.54.0，在临时仓库里试的）：
  1. 文件夹不在原处、记录还在时，主文件夹里 `git switch <那个分支>` 会失败：`already used by worktree at …`。所以记录必须清掉。
  2. 文件夹不在原处时，`git worktree remove <原路径>` 成功，只清这一条记录，分支留着，之后分支可以正常切换。
  3. 上了锁的记录 `remove` 会拒绝；`git worktree unlock <原路径>` 在文件夹不在时也能用，解锁后 `remove` 成功。
  4. HEAD 游离、上面有一个不在任何分支上的提交时，`git status --porcelain` 照样是空的。`git for-each-ref --contains <sha> refs/heads refs/tags refs/remotes` 没有输出，能认出这种情况。
  5. rebase 做到一半时，`git status --porcelain` 也可以是空的；worktree 的记录目录里有 `rebase-merge`。
  6. 记录清掉以后，文件夹里的文件都在，但 git 不再认它（`not a git repository`），`git worktree repair` 也修不回来。
  7. 把文件夹在原地改个名字，再 `git worktree remove <原路径>`，同样成功。这一步被拒绝时（试的是上了锁），把名字改回去，worktree 完好：`git status` 正常，记录还在。
  8. 只在暂存区里的内容，`git status --porcelain` 的两列都不是空格：试到 `MM`、`AM`、`AD`。暂存后磁盘上没再动的是 `A `，只改了磁盘的是 ` M`，没跟踪的是 `??`。

## 三、目标、不做、不能出的事

**目标**

1. Claude Code 页加页内标签：原来的内容叫「空间」，新的叫「运行中」。
2. 「运行中」列出开着的会话，和已关闭的会话留下的进程，可以手动结束。
3. 进程页把 Claude Code 的进程合成一行 `claude`，并在行上加小标签，点了跳到「运行中」。
4. Claude Code 页和 Codex 页的「空间」里各加一项「Agent worktree」，可以把整个 worktree 移走。

**这一批不做**

- 不自动结束，不到点结束，不发提醒或通知。
- 不在后台盯着进程。因此 seshka 靠常驻才有的那条线索（进程组）不做，会话换 ID 的记忆也不做。
- 不结束归不到 Claude Code 会话的进程。进程页的 CPU、内存两个标签不加结束按钮。
- 不在这里退出 Dock 上的 App。退出 App 是进程页和应用页已有的功能。
- 「运行中」不做 Codex、TRAE、Orca。
- 不做「保护名单」设置，不做跨会话的「全部结束」。
- 不清 `/private/tmp/claude-<uid>` 里的临时文件：在 Cleanzo 的删除范围之外，这台机器上只有 528 KB。
- 不做合盖不睡、统计卡片，不改菜单栏面板。
- worktree：不删分支，不运行 `git worktree prune` 或 `git gc`，不用 `--force`，不碰两处 agent 目录之外的 worktree。

**不能出的事**（技术上能跑也算失败）

- 结束了不该结束的进程：pid 被别的进程顶替；把运行 Claude Code 的编辑器当成了残留；把会话里打开、用户还在用的编辑器一起关了。
- 把还开着的会话的进程说成「已关闭的会话留下的」。
- 移走 worktree 时丢了东西：没提交的改动、只在暂存区里的内容、不在任何分支上的提交、做到一半的 rebase 或 merge。
- 移走之后分支切不过去。
- 密钥出现在界面、日志或任何文件里：环境变量的内容，和命令里 `NAME=值` 这种写法。
- Claude Code 的记录格式变了以后给出错的判断。读不到只能少显示，不能误判。
- 把进程页的 CPU 开销上限顶破。

## 四、做法的选择

**怎么集成**

| 做法 | 结果 |
|---|---|
| A. 在 Cleanzo 里用 Go 原生重做（选这个） | 保持单个二进制、macOS 12 起、一个菜单栏图标 |
| B. 带上或调起 seshka | 它是另一个 Swift App，要 macOS 14，自带菜单栏图标和设置 |
| C. 照搬它的读法：每次起 7 次 `ps`、最多 2 次 `lsof` | 进程页为了开销已经把 `ps` 压到 6 秒一次；原生读一遍只要 7 毫秒 |

**放在哪**

| 放法 | 结果 |
|---|---|
| 进程页第四个标签「Agent」 | 那一排是三种资源（CPU、内存、磁盘占用），「Agent」是按谁归类；里面只有 Claude Code |
| 「AI 与开发工具」里加一个入口 | 和上面的「Claude Code」分不清点哪个；只有一个工具时撑不起一个跨工具入口 |
| Claude Code 页内的标签，进程页只加跳转（选这个） | 不加新的顶层概念；以后 Codex 能支持了，在它那一页加同样的标签 |

维护者 11 月 21 日质疑了单独的「Agent」标签，改成第三种。

**怎么移走 worktree**

| 做法 | 结果 |
|---|---|
| seshka 的：干净的用 `git worktree remove` 直接删；有改动的进废纸篓再 `git worktree prune` | 干净的那种会永久删掉被忽略的文件（`.env`、`.vercel`）；`prune` 会顺带清掉仓库里别的失联记录，比如在没挂载的硬盘上的 worktree |
| 只进废纸篓，不动 git 的记录 | 分支切不过去（第二节第 1 条） |
| 先让 git 清掉这一条记录，再把文件夹移进废纸篓（选这个） | 文件都能从废纸篓找回；只清这一条记录；分支留着、能切换；git 那一步失败时什么都没动 |

## 五、「运行中」：读什么，怎么归属

一次读取叫一张快照。全部原生读，不调用 `ps`。

### 读取

1. 进程表：`unix.SysctlKinfoProcSlice("kern.proc.all")`，取 pid、父进程、进程组、账户、启动时间。
2. 本账户每个进程的参数和环境变量：`unix.SysctlRaw("kern.procargs2", pid)`。缓冲区依次是 `argc`（int32）、可执行文件路径、若干个 0、`argc` 个参数、环境变量，以空串结束。
   - 实现时改：路径连同结尾的 0 补齐到 8 字节的整数倍，参数从那里读起。不能把后面的 0 全跳过：第一个参数可以是空串，跳过它，最后一个「参数」就成了第一条环境变量。在这台机器的 636 个进程上核对过。
3. 环境变量只取三个：`CLAUDECODE`、`CLAUDE_CODE_SESSION_ID`、`CLAUDE_PID`。缓冲区用完就丢；其余变量不保存、不显示、不写日志、不进任何返回值。
4. 一个进程读不出任何环境变量，记为「看不到」。读出了环境变量但没有 `CLAUDECODE=1`，记为「没有标记」。两者要分开。
5. 会话记录：`~/.claude/sessions/<pid>.json`。同时满足这三条才算数：pid 活着；是本账户的；进程启动时间按 UTC 写成 `Mon Jan _2 15:04:05 2006`，和记录里的 `procStart`（把连续空格压成一个后）相等。最后一条防 pid 被顶替。每个字段都当可选。
6. 正在运行的 Dock 上的 App：已有的 `workspaceList()` 里 `Regular` 为真的那些。
   - 实现时改：这份列表读不到时，整张快照算读不到，什么都不列出。没有它就分不清 Dock 上的 App 和会话启动的命令。

### Claude Code 进程

有一份算数的记录的进程；或者没有记录、但 `argv[0]` 的文件名是 `claude` 的本账户进程。

- 父进程链上有另一个 Claude Code 进程的，是那个会话的子 agent，不单算一个会话。
  - 实现时改：两者之间隔着 Dock 上的 App 或它的辅助进程时除外，那个 Claude Code 进程单算一个会话。会话里直接跑起来的 App 自己启动的 `claude`，不该跟着外层会话一起被结束。
- 其余的各算一个会话。它的会话 ID 来自记录；没有算数的记录就是「会话 ID 未知」。

### 候选

本账户的进程，去掉这些：

- Claude Code 进程自己。
- Cleanzo 自己、它的子进程、它的父进程链（开发时 Cleanzo 可能就是 Claude Code 起的）。
- Dock 上的 App 和它们的辅助进程（可执行文件在那个 `.app` 里的）。不在 Dock 上的照常算，比如测试用的无界面浏览器。

### 一个候选带着哪个会话 ID

按顺序，前面的先定：

1. **标记。** 环境里有 `CLAUDECODE=1`：`CLAUDE_CODE_SESSION_ID` 的值。
2. **输出文件。** Claude Code 把每条命令的输出写到 `…/claude-<uid>/<项目>/<会话 uuid>/tasks/<名字>`。「看不到」的进程，标准输出或标准错误（fd 1、2）指着这样的路径：取路径里的会话。用 `proc_pidfdinfo(PROC_PIDFDVNODEPATHINFO)` 读。
3. **跟着子进程。** 「看不到」的进程，有一个子进程已经带了会话 ID：跟它一样。一轮一轮往上传，最多 5 轮。
4. **跟着父进程。** 「看不到」的进程，父进程已经带了会话 ID，或者父进程就是 Claude Code 进程：跟父进程的会话。

「没有标记」的进程永远不带会话 ID：它是被特意这样启动的。只和别的进程同一个进程组，不算线索。

### 能不能列出：看它上面是谁

从一个带了会话 ID 的候选往上走父进程链，直到 launchd（pid 1）。

- **链上只有同一个会话的候选，最后到了一个 Claude Code 进程。** 它属于这个 Claude Code 进程的会话，会话开着。就算它带的是旧 ID 也一样：`/clear` 之后 Claude Code 换 ID，但不重启它已经起的进程。
- **链上只有同一个会话的候选，最后到了 launchd。** 它已经和启动它的进程脱开了，再看下面「会话还开着吗」。
- **链上碰到别的东西**（Dock 上的 App、「没有标记」的进程、别的会话的进程、Cleanzo）。不列出。它是经由别的东西启动的，那个东西碰巧带着标记，比如从会话里打开的编辑器里的终端。

### 脱开的进程：会话还开着吗

实现时改：按会话 ID 整体判，不逐个进程判。带着同一个 ID 的脱开进程一起算开着、说不准或已关闭。

- **开着**：这个 ID 是某个 Claude Code 进程（子 agent 也算）现在的会话 ID；或者带着这个 ID、能列出的进程里（挂在会话下面的也算），有一个的 `CLAUDE_PID` 指着活着的 Claude Code 进程。
- **说不准**，不算开着并且以下任何一条成立：有 Claude Code 进程（子 agent 也算）读不到会话 ID；其中一个进程的 `CLAUDE_PID` 上有一个比它启动得早的活进程；进程表里同一个 pid 出现了两次。不列出，只在页脚计数。
- **已关闭**：其余情况。

原来的写法是逐个进程判。那样，一个靠 `CLAUDE_PID` 判成开着的命令，它那些看不到环境变量的子进程只继承了会话 ID，会被说成已关闭的会话留下的。

「已关闭」的才叫**残留进程**。

### 合并成一行

- 开着的会话里，和它的 Claude Code 进程同一个进程组的进程，是会话自己的辅助进程（MCP 服务器之类）。它们并进会话那一行：算进会话的占用，不单独列出，不能单独结束。
- App 的辅助进程（路径在同一个 `.app/Contents/` 里、父进程链通到那个 App）并进 App 那一行。
- Claude Code 包命令用的那层 shell 并进它所在进程组的第一行。它长这样：进程组长，是 `zsh`、`bash` 或 `sh`，命令行里有 ` eval '<命令>' < /dev/null`。它单独存在时，显示成里面的命令。

### 每一行的细节

只对要列出的进程读，通常不到 20 个。

- 内存：已有的 `proc_pid_rusage` 的 footprint，并进来的进程一起算。
- 运行了多久：启动时间。
- 所在文件夹：`proc_pidinfo(PROC_PIDVNODEPATHINFO)` 的当前目录。文件夹在一个 linked worktree 里时，显示 worktree 的名字。
- 监听的 TCP 端口：`/usr/sbin/lsof -nP -iTCP -sTCP:LISTEN -a -p <pid 列表> -Fpn`，走已有的 `spawnOutput`，3 秒为限。失败就不显示端口，不报错。
- 命令：参数拼起来，去掉那层 shell。显示前做两件事：去掉开头的 `NAME=值`；参数名里有 key、token、secret、password（不分大小写）的 `--名字=值` 和 `--名字 值`，值换成 `…`。
  - 实现时改：别处的 `NAME=值` 也把值换成 `…`，不论名字：命令中间的、`sh -c` 的脚本里的、紧跟在 `;`、`&`、`|`、`(` 后面的、`--flag=NAME=值` 里的。URL 里的账号密码换成 `…`。最后拼成一行，最多 300 个字符。

### 会话的细节

- 项目：记录里 `cwd` 的文件夹名；没有记录就读进程的当前目录。
- 标题：记录里的 `name`。已关闭的会话没有记录了，标题从 `~/.claude/projects/*/<会话 ID>.jsonl` 末尾 2 MB 里最后一条 `ai-title` 取（字段 `aiTitle`）；取不到就只显示项目，或「未知会话」。
- 空闲：记录里 `status` 是 `idle`。空闲了多久是现在减去 `statusUpdatedAt`。
  - 实现时改：记录里没有 `statusUpdatedAt` 时，状态当作读不到，不显示「空闲」，也不计入标签上的数字。
- 在哪里运行：负责进程（已有的 `nativeResponsiblePid`）所在的 App 的名字，如「Ghostty」。找不到就不显示。
- 占用：它的 Claude Code 进程、子 agent 和辅助进程加在一起。也就是结束这个会话能腾出的数。它启动的命令另算，各占一行。

## 六、「运行中」：界面

Claude Code 页的页头右侧加分段标签「空间 | 运行中」，用进程页和应用页同一个组件。别的工具的页面没有标签，Windows 上也没有。

- 进这一页默认在「空间」，和现在一样等用户点扫描。从进程页的小标签进来，直接开在「运行中」。
- 「运行中」标签上有一个数字：残留进程的行数，加上空闲超过 2 小时的会话数。进这一页时读一次。是 0 就不显示。
- 「空间」里扫描后那条「Claude Code 正在运行」的提示，加一个「看运行中」的链接，点了切标签。

```
    node next dev · 端口 3000 · 项目 C · 2 天         410 MB   [结束]
    python -m http.server · 端口 8000 · 5 小时        22 MB    [结束]

只列出能确定属于 Claude Code 会话的进程。另有 2 个带着它的标记、但说不准的，没有列出。
空闲时间来自 Claude Code 自己的记录。
```

- **开着的会话**：空闲最久的排最前，在干活的排最后。能展开，里面是它启动的、已经运行满 60 秒的命令（不满 60 秒的多半是一条马上结束的命令）。
- **已关闭的会话留下的进程**：按会话分组，最老的在前。没有时写「没有已关闭的会话留下的进程」。
- 有 Claude Code 进程读不到会话 ID 时，这一段写「读不到 Claude Code 的会话记录，没法判断哪些进程是留下的」。
- 两段都空：「Claude Code 没在运行，也没有留下进程。」
- 读不到 `status` 的会话照样列出，只是没有「空闲 N」。
- 标签显示着、窗口没隐藏时每 5 秒读一次，否则不读。有「刷新」按钮。结束之后立刻读一次。
- 有确认框开着、或正在结束时，列表不重排（和进程页一样）。

## 七、结束进程和会话

**能结束什么**：一个列出的进程（连同并进它那一行的进程）；一个已关闭的会话留下的全部进程；一个开着的会话。别的都不能。

**结束一个会话**，结束的是它的 Claude Code 进程、子 agent 和辅助进程。它启动的命令不动：会话没了以后，它们出现在「已关闭的会话留下的进程」里，要不要结束另外决定。

Cleanzo 自己父进程链上的会话照常列出，但没有结束按钮：结束它会连 Cleanzo 一起带走。

**每次都先问**

| 结束什么 | 确认框说什么 |
|---|---|
| 一个进程 | 它是哪个会话的；占着哪个端口，结束后这个端口停止服务 |
| 一个已关闭会话的全部 | 列出每一个进程和端口 |
| 空闲的会话 | 对话已经保存，之后可以用 `claude --resume` 接着聊；它启动的 N 个命令会留着 |
| 不是空闲的会话（在干活，或读不到状态） | 它可能正在干活，结束会打断当前这一步。按钮用危险样式 |

会话的 `entrypoint` 不是 `cli` 时，确认框多一句：它是「某 App」启动的，结束后那边的这个会话会断开。

**动手之前再核对一遍。** 请求里带每个目标的 pid 和启动时间。后端重新读一张快照，要求每个目标：pid 和启动时间都没变；是本账户的；不是 pid 0 或 1；按第五节的规则仍然是同一个会话下列出的进程，或者仍然是那个会话的 Claude Code 进程。不满足的跳过，结果里写「已经变了」。

实现时加：结束会话的请求还带着用户看到的会话 ID 和状态。ID 变了（`/clear`），或者看到时空闲而现在不是，就不结束，结果写「已经变了」。

**怎么结束**

1. 对每个目标 pid 发 `SIGTERM`。只对单个 pid 发，不对进程组发。
2. 每 100 毫秒看一次，最多等 2 秒。
3. 还活着的，再核对一次 pid 和启动时间，发 `SIGKILL`，再最多等 1 秒。
4. 每个目标的结果：已结束、强制结束、还在运行、已经变了。发信号时进程已经不在，算已结束。

**报告腾出了多少**：动手前读到的 footprint，只算确实已经不在的进程。提示写「已结束 3 个进程，腾出 1.2 GB」。还在运行的用错误提示说明。

## 八、进程页

**名字。** Claude Code 的进程合成一行 `claude`。规则：可执行文件在名叫 `versions` 的文件夹里、文件名和内核短名字相同时，名字取 `versions` 上一级文件夹的名字，去掉开头的点。`…/claude/versions/2.1.321` 和 `~/.claude/versions/2.1.304` 都得到 `claude`。`TestGroupProcessesUsesKernelNames` 补上这台机器的情况。

**跳转标签**

- `claude` 那一行：有空闲超过 2 小时的会话时，显示「N 个空闲会话」。
- 任何一行里有残留进程时：显示「N 个是已关闭会话留下的」。残留进程属于哪一行，用进程页自己的归类函数（`ownProcessKey`）算，在 Go 里算好再给页面。
- 点了都跳到 Claude Code 页的「运行中」。
- 一行可以同时有这个标签和现有的磁盘增长标签。
- 每次进进程页读一次，和现在读磁盘增长摘要的时机一样。不随每 2 秒的采样读，也不读端口。
- 没装 Claude Code（`ListAITools` 里没有）就不读。

## 九、worktree：找、判定、移走

**放在哪。** Claude Code 页和 Codex 页的「空间」里各加一项「Agent worktree」，排在可清理的各项之后、「保留」那一组之前。徽标用「敏感」。展开后一个 worktree 一行：勾选框、名字、「仓库 · 分支 · N 天没动」、状态说明、大小、在访达中显示。

- 从不预先勾选。
- 复用现有的「一项分成几组」的行，但不带对话记录的那套（7/30/90 天的窗口、最近 24 小时保留）。
- 不计入页头的「可清理」。勾了才计入「清理」按钮上的数。
- 页头的「占用」是工具自己那个文件夹的大小，这一点不变。Claude Code 的 worktree 在各个仓库里，不计入；Codex 的在 `~/.codex/worktrees` 里，本来就计入，现在只是从「保留」里那条认不出的 `worktrees` 变成这一项。
- 「AI 空间」页不显示它，也不把它算进任何一类（`ScanAITools` 不返回这一项，`ScanAITool` 才返回）。
- 垃圾清理里「开发项目」那一组不变，照旧列闲置 worktree 的构建产物。

**去哪里找**

- Claude Code：各仓库的 `<仓库>/.claude/worktrees/*`。仓库来自两处的并集：`~/.claude/projects` 里每个项目的对话记录写的 `cwd`，加上开着的会话的 `cwd`，各自往上找到带 `.git` 的文件夹（`.git` 是文件时，顺着它找到主仓库）；以及现有的主目录遍历（`findBuildFolders` 用的那套规则）走到的 `.claude/worktrees`。只靠对话记录不够：用 Cleanzo 清掉旧对话以后，仓库就找不到了。
- Codex：`~/.codex/worktrees/<id>/<名字>`。

**什么才算一个 worktree。** 文件夹里的 `.git` 是普通文件，`gitdir:` 指向某个 `<公共目录>/worktrees/<名字>`，那个记录目录存在，并且里面的 `gitdir` 文件指回这个文件夹的 `.git`。不满足的文件夹列出来，写「认不出，Cleanzo 不动」，不能勾。

文件夹还必须过 Cleanzo 现有的删除范围检查（在主目录里、不在保护的目录里）。不过的不列出。

**Codex 在运行时，Codex 这一项整项不能勾**，显示「先退出」，和它别的项一样（现有的 `running && !RunSafe`）。Codex 没有能判断「哪个 worktree 正被 agent 用着」的记录，只能整项等它退出。Claude Code 几乎总有会话开着，它这一项按下面的表逐个判断。

**状态**，按顺序判定，命中就停。扫描时判一次，移走前再判一次。

| 状态 | 条件 | 能勾吗 |
|---|---|---|
| 在用 | 本账户任何一个进程的当前目录在里面；或开着的会话的 `cwd` 在里面；或记录目录里的 `locked` 写着 `(pid N)`，N 是一个活着的进程，并且它的启动时间早于 `locked` 的修改时间；或 `locked` 存在但认不出这种写法（有人特意锁的） | 不能 |
| 里面还有别的 worktree（实现时加） | 它的 `.claude/worktrees` 里有文件夹；或仓库里别的 worktree 记录指着它里面的文件夹 | 不能。先移走里面的 |
| 含子模块 | 记录目录里有 `modules` | 不能 |
| 操作做到一半 | 记录目录里有 `rebase-merge`、`rebase-apply`、`MERGE_HEAD`、`CHERRY_PICK_HEAD`、`REVERT_HEAD` 或 `BISECT_LOG` | 不能 |
| 有不在任何分支上的提交 | 记录目录的 `HEAD` 不是 `ref: refs/heads/…`，并且 `git for-each-ref --contains <sha> --count=1 refs/heads refs/tags refs/remotes` 没有输出 | 不能 |
| git 没能回答 | 找不到 git；`/usr/bin/git` 是没装开发者工具时的占位程序；超时；出错；（实现时加）reftable 格式的仓库，记录目录的 `HEAD` 读不出真的分支 | 不能 |
| 暂存区里有和磁盘上不一样的内容 | `git status --porcelain` 有一行，第一列不是空格、`?`、`!`，第二列也不是空格（`MM`、`AM`、`AD`、`UU` 等）。这种内容只在暂存区里，暂存区跟着记录一起没了，废纸篓里找不回 | 不能 |
| 有没提交的改动 | `git status --porcelain` 有别的输出（改过的、暂存的、没跟踪的） | 能，行上写「N 处没提交的改动，会一起进废纸篓」 |
| 干净 | 以上都不是 | 能 |

`locked` 里写的 pid 已经不在，或者那个 pid 上的进程比锁还新，是过期的锁，不算在用。

**对 git 说话的规矩**，和现有的 `gitCheckIgnore` 一样：去掉继承来的 `GIT_*` 环境变量；`GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0`、`-c core.fsmonitor=false`；有时间限制；git 用 `findTool("git")` 找，`/usr/bin/git` 要先过 `developerToolsInstalled`。对仓库说话时用记录目录里 `commondir` 指的公共目录（`--git-dir`），不假设主文件夹在哪。各个 worktree 的 `git status` 并行跑，并行数用 `scanConcurrency`。

实现时加：只读 git 的标准输出（警告写在标准错误上，混进来会被当成一行状态）；git 在自己的进程组里跑，超时或结束后整组结束。

**移走**，每个勾选的 worktree 依次做：

1. 重新找到它，重新判状态。不再能勾，或者状态和用户看到的不一样（比如干净变成了有改动），跳过，结果写「已经变了」。
2. 现有的占用探测（`probeUsage`）说里面有打开的文件：跳过，算「正在使用，已保留」，和别的项一样。
3. 有过期的锁：`git worktree unlock <路径>`。
4. 把文件夹在原地改一个临时名字（同一个上级文件夹里）。
5. `git worktree remove <原路径>`。原路径上已经没有文件夹，git 只清掉这一条记录。失败：把名字改回去，报告「没能清掉 git 的记录，什么都没动」，这一个到此为止。
6. 把名字改回去。
7. 把文件夹移到废纸篓（`trashWithContext`）。失败：报告「git 的记录已经清掉，文件夹还在原处，没能移到废纸篓」。这时文件没丢，分支能切。

第 4 到 6 步是为了让第 5 步失败时能完全退回去。先进废纸篓再清记录的话，清记录失败会留下一个切不过去的分支。

实现时加：

- **同一时间只移一个。** 从重新判状态到进废纸篓持一把锁，扫描的「改回原名」也等这把锁。不然另一次扫描可能在第 5 步之前把文件夹改回原名，git 看到文件夹还在，会把它连同被忽略的文件直接删掉。仓库设了 `status.showUntrackedFiles=no` 时，带着没跟踪文件的也会被删。
- **先量大小，再重新判状态。** 量大小要走完整个文件夹，放在判定之后的话，这段时间里的改动看不到。
- **第 5 步成不成，看记录目录还在不在**，不看 git 的退出码。git 清掉记录以后才超时，也算清掉了。
- **取消。** 改名之前取消，什么都不动；改名之后一直做到进废纸篓为止。
- **扫描时把移到一半的放回原名。** 文件夹带着 Cleanzo 的临时后缀、原名空着：记录还指着原路径，或者记录已经没了（这时放回去以后是「认不出」），就改回原名。这是扫描唯一会改磁盘的地方。

腾出的大小是移走前量的，量法和这一页别的项一样。

**确认框对 worktree 说的话**：文件夹进废纸篓；分支和已提交的内容留在仓库里；放回原处后文件都在，但它不再是 git 的 worktree，要接着做就在仓库里重新 `git worktree add`，或直接切到那个分支。勾了有改动的，另加一句有几个带着没提交的改动。

## 十一、开销

- 一张快照在这台机器上约 7 毫秒，加上有要列出的进程时的一次 `lsof`。
- 端口只在要列出的 pid 集合变了、或距上次读满 30 秒时重读。
- 上限沿用进程页的：「运行中」标签开着时，Cleanzo 主进程加它的子进程合计不超过一个核的 3%，量法相同（getrusage 的 SELF 加 CHILDREN）。发版前量一次。
- 进程页的摘要每次进页面读一次，不读端口。

## 十三、风险

| 风险 | 怎么处理 |
|---|---|
| Claude Code 改了标记或记录的格式 | 每个字段都可选；读不到就少显示；说不准的不列出 |
| pid 被顶替 | 记录要对上 `procStart`；结束前核对 pid 和启动时间，升级到 `SIGKILL` 前再核对一次 |
| 把编辑器或编排工具当成残留 | 同组不算线索；「没有标记」的不列出；Dock 上的 App 不进候选；链上碰到别的东西就不列出 |
| 从会话里启动的 tmux 之类一直带着标记，之后在里面跑的东西也带 | 会被列成残留。从不预选，每次确认，确认框列出每一个进程的命令 |
| 用户还在用那个开发服务器 | 结束会话不动它启动的命令；逐个确认，确认框写明端口 |
| 结束了别的 App 托管的会话 | 确认框写明是哪个 App 启动的 |
| 密钥泄露 | 环境变量只取三个，其余当场丢弃；命令显示前遮掉赋值和带 token 的参数；有测试。参数里别的写法的密钥遮不到 |
| 移走 worktree 丢了工作 | 第九节的状态表；一律进废纸篓；移走前重判 |
| 仓库里的恶意 git 配置 | 关掉 fsmonitor、不加可选锁、不弹提示、有时间限制；只运行 `status`、`for-each-ref`、`worktree unlock`、`worktree remove` |
| 清记录和进废纸篓之间出错 | 第九节第 5、7 步各自的退路 |
| 开销 | 第十一节的上限，发版前量 |

## 十四、裁定

**维护者定的**

- 不单独加「Agent」标签或入口（11 月 21 日质疑后改的）。
- worktree 移除和「运行中」同一批做（11 月 21 日）。这改掉了 11 月 17 日「Worktrees are never removed」那一条。

**写这份设计的人定的**，每一条都可以单独推翻：

1. 放在 Claude Code 页内，标签叫「空间」和「运行中」。维护者看过，没有反对。不叫「会话」，因为这个词在这两页里已经指磁盘上的对话记录。
2. 结束进程只给能确定属于 Claude Code 会话的进程和会话本身。这改掉了进程页设计里「不结束单个子进程」那一条；进程页的 CPU、内存标签仍然不能结束命令行程序。
3. 在干活的会话也可以结束，确认框更重。卡住几天的会话也会显示成在干活。
4. 结束会话不动它启动的命令。seshka 是一起结束的；这里分两步，免得把用户还在用的开发服务器关掉。
5. Dock 上的 App 不在这里列出，也不在这里结束。
6. 说不准会话是否还开着的进程不列出，只计数。宁可漏掉残留，不把开着的会话的进程说成残留。
7. 「空闲超过 2 小时」才计入标签上的数字和进程页的小标签。固定，不给设置。
8. 开着的会话里，运行不满 60 秒的命令不列出。
9. 每 5 秒读一次。
10. 不做进程组那条线索和换 ID 的记忆。代价：已关闭的会话如果换过 ID，它留下的进程可能取不到标题；只留下 macOS 自带程序、又没有别的线索的残留认不出来。实现时补的一条代价：`/clear` 之后，带着旧 ID 的脱开进程，如果带这个 ID 的进程里没有一个有 `CLAUDE_PID`，会被列为「已关闭的会话留下的」，虽然那个 Claude Code 进程还开着。一张快照分不出这两种情况。
11. 进程页把 Claude Code 的进程合成一行 `claude`。现在显示成版本号是个错，顺带改掉。
12. worktree 一律进废纸篓，包括干净的。
13. 有没提交改动的 worktree 可以勾，行上和确认框里都写明。暂存区里有独有内容的不能勾。
14. 认不出的、上了别人的锁的、含子模块的、操作做到一半的、HEAD 上有独有提交的、git 答不上来的，都不能勾。
15. Codex 的 worktree 一起做，规则相同，外加「Codex 在运行时整项不能勾」。这一半在维护者的机器上没有样本可验，只有测试。
16. worktree 不进「AI 空间」。
17. 主目录之外的仓库里的 worktree 不列出。
18. 功能说明里写明思路来自 seshka。

**实现时定的**（2026-11-21，都是评审指出、规格没写到的情况，每一条都可以单独推翻）：

19. 脱开的进程按会话 ID 整体判开着、说不准还是已关闭（第五节）。
20. 任何一个 Claude Code 进程读不到会话 ID，就不判定残留；原来只看单算会话的。
21. Dock 上的 App 里跑的 Claude Code 单算一个会话。
22. 命令里任何位置的 `NAME=值`、URL 里的账号密码都遮掉。
23. 运行中的 App 列表读不到时，「运行中」显示读取失败，不显示列表。
24. 记录里没有 `statusUpdatedAt` 的会话当作读不到状态。
25. 结束会话时核对用户看到的会话 ID 和状态。
26. worktree 多一种状态「里面还有别的 worktree」，不能勾。
27. 移走 worktree 加锁、先量后判、以记录目录为准、改名后不再响应取消；扫描把移到一半的放回原名。
28. 「Agent worktree」这一项自己没有勾选框，只能一个一个勾。
29. 读不到进程的当前目录时，所有 worktree 都算在用。
30. worktree 移走失败时用错误提示说明是哪一个、为什么；不止一个时说还有几个。
