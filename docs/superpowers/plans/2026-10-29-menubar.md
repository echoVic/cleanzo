# Menu Bar Readings and Their Panels — Implementation Plan

> **For agentic workers:** In this project the tasks are executed by traecli and the Codex CLI (see "Execution batches"). **Executors do not commit**: the reviewer checks and commits each task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** On macOS, Cleanzo's menu bar shows live readings, CPU and memory by default and optionally GPU, network, disk, temperature and battery, each as a two-line item (a small name above its value). Clicking a reading opens its own panel: a big number, a one-line diagnosis, a one-minute chart, details, and for CPU and memory the five apps using the most, which can be quit from the panel. Settings gets a 「菜单栏」 section with the readings and the login switch.

**Architecture:**
- **Task 1 (Go, pure + drawing + sampling):**
  - `menubar_readout.go` turns a reading into the two lines an icon shows, and gives each reading a fixed width.
  - `menubar_draw_darwin.go` draws those lines with AppKit into an 18-point-tall PNG: a template image normally, a colored one for memory under pressure.
  - `menubar_sample.go` reads only what the shown readings need, every 2 s. It reuses the home page's reads; `machineReader.readSome` reads just the GPU, network or chip temperature.
- **Task 2 (Go + one listener in `main.ts`), the resident app:**
  - `menubar.go` keeps the chosen readings in `menubar.json`, with a layout number that renames the icons when the set changes. It binds `MenuBar`/`SaveMenuBar` and the `menubar:updated`/`menubar:go` events.
  - The controller in `menubar_darwin.go` makes the icons from right to left after removing the Cleanzo icon, which `growth_app.go` makes again leftmost. It feeds them from the sampler on the main thread.
  - The growth lifecycle becomes the resident lifecycle. The app stays open while monitoring is on or a reading shows, and opening at login follows the same rule. The Cleanzo icon's menu gains 「菜单栏设置…」.
- **Task 3 (Go + process page):**
  - Clicking a reading toggles a popover flyout that loads `panel.html?item=<reading>`.
  - Bound methods: `WatchMenuBarPanel` streams the status samples the panel needs, reading only what it shows. `MenuBarOpen` closes the panel and shows a page of the main window. `MenuBarHold` keeps the panel open while a quit is pending.
  - The 进程 page scrolls to and highlights a CPU or memory row that a panel named.
- **Task 4 (web):**
  - a second Vite entry, `panel.html` and `src/panel/`;
  - the panel page: pure rules in `format.ts`, the component in `PanelApp.tsx`;
  - the home page's chart moves to `src/react/status/Spark.tsx` so both pages use it;
  - the dev mock, so `panel.html?item=cpu&mock` renders in a browser.
- **Task 5 (web + docs):** the Settings 「菜单栏」 section, the login switch moved into it, the 「菜单栏设置…」 scroll, the strings, README and CHANGELOG.

**Tech Stack:** Go 1.27.3, mygo 0.7.1 (`NewTray`, `NewFlyout` with `Popover`/`FitContent`, `CallerWindow`), purego v0.11.1 with its objc package (structs pass and return by value on macOS). TypeScript, React 19, Vite 8 (rolldown), bun test. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-menubar-design.md` (Chinese), approved by the maintainer (「ok」, 2026-10-29). Mockup: `.superpowers/brainstorm/80442-1793257752/content/menubar-v1.html` (not in the repository).

## Global Constraints

- **macOS only.** Windows shows no readings, no panels, no 「菜单栏」 section, and its behavior is unchanged (spec §二, §八.6). Windows code paths compile against stubs in `menubar_other.go`.
- **Defaults:** CPU and memory on, the other five off (spec §三.2). With no `menubar.json` the defaults apply, so an update shows the two readings.
- **Order:** left to right, the Cleanzo icon, then `cpu, mem, gpu, net, disk, temp, battery`. When the set of readings changes, all of them are made again in this order. When it doesn't, the icons keep the places the user ⌘-dragged them to (spec §三.3).
- **Battery:** never offered or shown on a Mac without one (spec §三.5).
- **Readings:**
  - two lines: a small label (`CPU 内存 GPU 磁盘 温度 电池` / `CPU MEM GPU DISK TEMP BAT`) above the value;
  - the network has no label: `↓156K` above `↑55K`;
  - memory is used ÷ total, the home page's memory card numbers, and only memory changes color: orange under pressure, red when critical;
  - the disk value is `26.7 GB 可用` / `26.7 GB free`;
  - every reading updates every 2 s, and an icon's width doesn't change with its value (spec §三.1).
- **Panels:** clicking a reading opens its panel below it; clicking it again or anywhere else closes it (spec §四). From top to bottom:
  - a name and a big number;
  - a sub-line;
  - a one-line diagnosis;
  - a chart of the readings since the panel opened, at most 30 points (1 minute);
  - details;
  - for CPU and memory, the top 5 rows of the 进程 page's list (apps, command-line programs and system processes; estimates marked 「≈」); for disk, the 5 apps that grew most in 7 days, from growth monitoring, only while monitoring is on;
  - footer links.

  Values that can't be read are left out; a big number that can't be read shows 「—」.
- **Quitting from a panel** (spec §四.5) goes in two clicks:
  1. 「退出」 shows on hover; the first click turns it into 「确认退出」 and the second quits.
  2. The quit itself is the 进程 page's: `quitApp`, then after 5 s 「还没退出」 with 「强制退出」, which takes two clicks too.

  The list keeps its order while the pointer is in it, and the panel stays open while a quit is pending. Clicking a name opens 进程 at that row.
- **Cost** (spec §六), main process plus children, with the window closed:
  - ≤ 0.3% of one core with the two default readings and panels closed;
  - ≤ 0.6% with all seven;
  - ≤ 3% with a panel open, and the panel's web process ≤ 3%.

  With panels closed: no process list and no child process. If an open CPU or memory panel is over 3%, drop the other-accounts `ps` read first.
- **Lifecycle** (spec §七):
  - any reading shown keeps Cleanzo running when the window closes;
  - 「开机时启动」 can be checked while a reading shows or monitoring is on; at login only the menu bar appears;
  - turning monitoring off keeps the login item unless no reading shows;
  - with both off, the login item is removed and the switch is disabled.
- **Platform rules** (enforced by `testenv_test.go`):
  - exported Go names and `Cleaner` methods live in untagged files; `_darwin.go` and `_other.go` hold unexported names only (`TestBindingsArePlatformNeutral`);
  - untagged non-test `.go` files build paths with `filepath` (`TestNoSlashPathLiterals`): the flyout URL `"/panel.html?item="` lives in `menubar_darwin.go`.
- **Bindings are generated.** After changing bound types, methods or events, run `bun run generate`. Never edit `src/mygo.ts` by hand.
- **i18n:**
  - every new key exists in `zh` and `en`, in `src/native-i18n.json` (Go-drawn text) or `src/i18n.ts` (pages);
  - no value contains macOS terms (`Mac`, `macOS`, `Dock`, `Finder`, `系统设置` …): `tests/i18n-windows.test.ts` checks every key, native ones included.
- **Comments and copy** follow the file they're in: English in Go, Chinese in TS/TSX/CSS.
- **No new dependencies**, Go or npm. No commands that need the network.
- **Executors do not commit.** Leave the changes in the working tree.
- **Safety on the maintainer's Mac:** never use AX automation to press quit buttons; capture only Cleanzo's own windows (`screencapture -x -o -l <windowid>`); launch test builds with `open -g`.

## Review Focus

1. **Threads.**
   - Icons, flyouts, `growthTray` and the controller's maps belong to the main thread.
   - The sampler's goroutine only reads and hands each reading over through `mygo.RunOnMain`.
   - Nothing on the main thread takes `growthConfigMu`. `SaveMenuBar`, like `SaveGrowthConfig`, holds it while it waits for the main thread.
2. **Order and names.**
   - Readings are made right to left after `hideGrowthTray`, and `showGrowthTray` runs after them, named for the same layout.
   - The layout changes only when a non-empty set changes.
   - The Cleanzo icon is named `cleanzo.<layout>` at every layout. Changed in fix round 1: macOS saves a position for every named status item, so the old name `growth` would put the icon back right of the new readings.
3. **Login rule.**
   - `validateGrowthConfig(c, menuBar)` keeps `OpenAtLogin` only when monitoring is on or `menuBar` is true.
   - `loadGrowthConfig` no longer clears it.
   - `turnOffGrowth` starts from the system's login item and keeps it only with readings on.
   - `SaveMenuBar` clears it when the last reading goes and monitoring is off.
4. **Cost.**
   - With panels closed: no process reads, no child process.
   - The machine reader opens only for GPU, network or temperature, and `readSome` reads only those.
   - An icon is redrawn only when its text changed, or when the menu bar's appearance changed and the icon is colored.
5. **AppKit and purego.**
   - Every allocated object is released or autoreleased; drawing happens inside `withPool`.
   - Struct arguments and returns (`NSRect`, `NSSize`) are only used through `objc.Send`.
   - A nil font or class bails out instead of reaching an array insert, which would raise an exception.
6. **Unknown values** are never blank, 0, NaN or `-1` on screen.
   - Icons write `—`.
   - Panels leave the row out, and write `—` for an unreadable big number.
7. **Windows:** compiles, behaves as before, `GOOS=windows go vet ./...` is clean.

## Decisions this plan makes

The spec leaves these to the builder (§九). Reviewers, please check them.

- **Drawing:**
  - The two lines are drawn with AppKit text into an image 18 points tall at 2× (`drawWithRect:options:attributes:` with options 0, which puts each line on a fixed baseline). The label is 7.5 pt medium at 55% opacity, the value 11.5 pt semibold with tabular digits; the network's two values are 9 pt.
  - A spike (`/tmp/czt/readoutspike`, 2026-10-29) ran this code through purego on the maintainer's Mac. The struct arguments and returns work, and of the 36 pixel rows `CPU` inks rows 3–13, `51%` rows 16–33 and `内存` rows 1–15.
  - The image is a template, so macOS tints it for light and dark menu bars and the highlight. Only memory under pressure draws in color, in the menu bar's ink from `Tray.Dark()`, with the value in `#B45309`/`#FFC35A` (warn) or `#D92D20`/`#F0666A` (critical) for a light/dark bar: the page's `--warn`, `--warn-text`, `--danger` and `--danger-strong`.
- **Width:**
  - Each icon keeps the width of its widest usual text (`100%`, `100°`, `↓000M`, `000.0 GB 可用`). If a value is wider, the icon widens once and never narrows back (a high-water mark, fix round 1).
  - Text is left-aligned, as in the mockup.
- **Notch:** no special handling. The icons are compact, and only two show by default. macOS hides status items that don't fit, as it does for every app.
- **Panels:**
  - The system popover (`Popover: true`): its own material, arrow and highlight of the icon, and it closes on outside clicks.
  - 320 points wide, as tall as the content up to 640.
  - The page has no background of its own.
  - One panel at a time: opening one closes any other.
  - Each opening creates a new flyout and closing destroys it, so a closed panel costs nothing.
- **Panel data:**
  - The panel streams the home page's `StatusSample` through `WatchMenuBarPanel`, which reuses the status loop with a source that leaves out what that panel doesn't show:
    - the machine reader for memory and battery;
    - `system_profiler` for every panel but battery (the temperature panel reads the battery's temperature from AppleSmartBattery).
  - CPU and memory panels also open the 进程 page's `watchProcesses` stream for their list and diagnosis.
  - Specs (`machineInfo`, `info`) and growth records (`growthState`) are read once per opening.
  - Nothing is shared with the home page's own stream; each is opened and closed with its page.
- **Diagnoses** (one sentence each):
  - **CPU:** busy is the 进程 page's rule, 3 samples in a row at 80% or more, with its sentence; otherwise 「CPU 不忙，占得最多的是 X（N%）。」
  - **Memory:** pressure warn or critical uses the 进程 page's sentence; normal 「内存够用，占得最多的是 X（N GB）。」 Either way the home page's swap line is added when swap takes 1 GB or more of disk.
  - **GPU:** busy at 80% for 3 samples.
  - **Network:** the connection's kind.
  - **Disk:** the home page's low-space sentence below 20 GB, else 「可用空间充足」, plus the home page's largest growth alert while monitoring is on.
  - **Temperature:** the thermal state, four levels.
  - **Battery:** the home page's charging state, plus 「建议维修」 when its condition says so.
- **Charts:**
  - CPU, memory (colored by pressure), GPU, battery and temperature on 0–100.
  - Network download on the minute's maximum, with a 100 KB/s floor.
  - Disk read+write on the minute's maximum, with a 1 MB/s floor.
- **Storage:**
  - `menubar.json` next to `config.json` holds the readings and the layout number.
  - The login choice stays in the growth settings (`GrowthConfig.OpenAtLogin`), so existing users keep it. Its rule widens to "monitoring on or a reading shown".
  - Settings' login checkbox, now in 「菜单栏」, still saves it through `saveGrowthConfig({ openAtLogin })`.
- **Cleanzo icon:**
  - It keeps its picture. It's named after the layout (`cleanzo.<layout>`), like the readings, so that it's made leftmost whenever they're made again. This was decided in fix round 1; the plan first kept the name `growth` at layout 0.
  - Its menu: the growth lines while monitoring is on, then 「打开 Cleanzo」, a separator, 「菜单栏设置…」 and 「退出 Cleanzo」.
  - Its tooltip is 「Cleanzo」 when only readings keep it.
- **Two-click confirm:**
  - 「确认退出」 and 「确认强制退出」 fall back after 3 s without the second click, or when the pointer leaves the list.
  - A failed force quit returns to 「还没退出」.

// menubar_readout.go turns what the menu bar readings read into the text their
// icons show (design: docs/superpowers/specs/2026-10-29-menubar-design.md
// §三.1): a small label above a value or, for the network, the download rate
// above the upload rate. The rules are pure, so they test on any platform;
// menubar_draw_darwin.go draws the text.

import (
	"fmt"
	"math"
	"strconv"
	"strings"
)

// menuBarReading is one sample of what the readings show. A reading that does
// not show is not read and stays unknown: CPU, GPU, NetDown, NetUp and
// Battery -1; MemTotal, Free and ChipTemp 0.
type menuBarReading struct {
	CPU      float64 // % busy, the whole CPU, as the home page's CPU card
	MemUsed  uint64  // bytes, the home page's memory used
	MemTotal uint64  // bytes
	Pressure uint64  // kern.memorystatus_vm_pressure_level: 1 normal, 2 warn, 4 critical
	GPU      float64 // % device utilization
	NetDown  float64 // bytes/s over Wi-Fi and Ethernet
	NetUp    float64 // bytes/s
	Free     int64   // bytes free on the startup disk
	ChipTemp float64 // °C, the hottest SoC die sensor
	Battery  int     // % charge
}

// unknownMenuBarReading is a reading before anything is read.
func unknownMenuBarReading() menuBarReading {
	return menuBarReading{CPU: -1, GPU: -1, NetDown: -1, NetUp: -1, Battery: -1}
}

// menuBarText is what one icon shows, Top above Bottom. With Label, Top is the
// reading's small name and Bottom its value; without, as for the network, both
// lines are values. Tone colors the value: "" as the menu bar's text, "warn"
// orange and "crit" red, for memory under pressure (spec §三.1).
type menuBarText struct {
	Top, Bottom string
	Label       bool
	Tone        string
}

// oneDecimal writes v with one decimal, halves rounded up as toFixed(1) rounds
// them on the page.
func oneDecimal(v float64) string {
	return strconv.FormatFloat(math.Round(v*10)/10, 'f', 1, 64)
}

// menuBarPct writes a percentage rounded to a whole number; "—" when unknown.
func menuBarPct(v float64) string {
	if !(v >= 0) { // NaN too
		return "—"
	}
	return fmt.Sprintf("%d%%", int(math.Round(math.Min(v, 100))))
}

// menuBarRate writes bytes per second the short way the menu bar has room for,
// in decimal units like the home page's rates: "156K", "1.2M", "12M", "1.3G";
// "—" when unknown. The unit is chosen after rounding, so it never writes
// "1000K".
func menuBarRate(bps float64) string {
	switch {
	case !(bps >= 0):
		return "—"
	case bps < 999.5e3:
		return fmt.Sprintf("%dK", int(math.Round(bps/1e3)))
	case bps < 9.95e6:
		return oneDecimal(bps/1e6) + "M"
	case bps < 999.5e6:
		return fmt.Sprintf("%dM", int(math.Round(bps/1e6)))
	case bps < 9.95e9:
		return oneDecimal(bps/1e9) + "G"
	default:
		return fmt.Sprintf("%dG", int(math.Round(bps/1e9)))
	}
}

// menuBarSize writes free space as the home page's disk card does (fmtMem in
// src/react/status/format.ts): 1024-based, from 1 GB on with one decimal and a
// trailing ".0" dropped, whole MB below; "—" when unknown.
func menuBarSize(n int64) string {
	switch {
	case n <= 0:
		return "—"
	case n >= 1<<30:
		return strings.TrimSuffix(oneDecimal(float64(n)/(1<<30)), ".0") + " GB"
	default:
		return fmt.Sprintf("%d MB", int(math.Round(float64(n)/(1<<20))))
	}
}

// menuBarTextFor is what item's icon shows for reading r (spec §三.1). text
// translates: nativeText, or a stand-in in tests.
func menuBarTextFor(item string, r menuBarReading, text func(string, map[string]string) string) menuBarText {
	label := func(value string) menuBarText {
		return menuBarText{Top: text("menubar.label."+item, nil), Bottom: value, Label: true}
	}
	switch item {
	case "cpu":
		return label(menuBarPct(r.CPU))
	case "mem":
		pct := -1.0
		if r.MemTotal > 0 {
			pct = float64(r.MemUsed) / float64(r.MemTotal) * 100
		}
		t := label(menuBarPct(pct))
		switch r.Pressure {
		case 2:
			t.Tone = "warn"
		case 4:
			t.Tone = "crit"
		}
		return t
	case "gpu":
		return label(menuBarPct(r.GPU))
	case "net":
		return menuBarText{Top: "↓" + menuBarRate(r.NetDown), Bottom: "↑" + menuBarRate(r.NetUp)}
	case "disk":
		if r.Free <= 0 {
			return label("—")
		}
		return label(text("menubar.value.free", map[string]string{"size": menuBarSize(r.Free)}))
	case "temp":
		if r.ChipTemp <= 0 {
			return label("—")
		}
		return label(fmt.Sprintf("%d°", int(math.Round(r.ChipTemp))))
	case "battery":
		if r.Battery < 0 {
			return label("—")
		}
		return label(fmt.Sprintf("%d%%", min(r.Battery, 100)))
	}
	return menuBarText{}
}

// menuBarWidest is the text item's icon keeps room for, so that it does not
// change width with its value (spec §三.1): its widest usual value. The digits
// all have one width, so 0 stands for any digit.
func menuBarWidest(item string, text func(string, map[string]string) string) menuBarText {
	if item == "net" {
		return menuBarText{Top: "↓000K", Bottom: "↑000K"}
	}
	w := menuBarTextFor(item, menuBarReading{}, text)
	w.Tone = ""
	switch item {
	case "disk":
		w.Bottom = text("menubar.value.free", map[string]string{"size": "000.0 GB"})
	case "temp":
		w.Bottom = "100°"
	default:
		w.Bottom = "100%"
	}
	return w
}

// menubar_sample.go reads what the menu bar readings show, every two seconds,
// while any shows (menubar spec §三.1, §六). It reads through menuBarSource,
// so the tests run on any platform; menubar_darwin.go wires the native reads.

import (
	"context"
	"slices"
	"time"
)

// menuBarSource is what the readings read. machine is opened only while the
// GPU, the network or the temperature shows.
type menuBarSource struct {
	cpu     func() (busy, total uint64) // cumulative ticks
	memory  func() MemoryStatus
	disk    func() DiskStat
	machine func() menuBarMachine // nil when it cannot be opened
	battery func() int            // % charge, -1 unknown
}

// menuBarMachine reads the live readings the menu bar can show; on macOS
// *machineReader has it.
type menuBarMachine interface {
	readSome(now time.Time, gpu, net, temp bool) *MachineSample
	close()
}

// Timing knobs, variables so tests can shrink them.
var (
	menuBarFirst = time.Second     // the first reading's interval, for the CPU and the rates
	menuBarEvery = 2 * time.Second // spec §三.1
)

// sampleMenuBar reads what items show, the first time after menuBarFirst and
// then every menuBarEvery, and hands each reading to show, until ctx ends. It
// reads only what the shown readings need (spec §六): no process, no child
// process. show runs on the sampler's goroutine.
func sampleMenuBar(ctx context.Context, items []string, src menuBarSource, show func(menuBarReading)) {
	has := func(item string) bool { return slices.Contains(items, item) }
	gpu, net, temp := has("gpu"), has("net"), has("temp")
	var machine menuBarMachine
	if (gpu || net || temp) && src.machine != nil {
		if machine = src.machine(); machine != nil {
			defer machine.close()
			machine.readSome(time.Now(), gpu, net, temp) // starts the rates' counters
		}
	}
	var prevBusy, prevTotal uint64
	if has("cpu") {
		prevBusy, prevTotal = src.cpu()
	}
	if sleepCtx(ctx, menuBarFirst) != nil {
		return
	}
	tick := time.NewTicker(menuBarEvery)
	defer tick.Stop()
	for {
		r := unknownMenuBarReading()
		if has("cpu") {
			busy, total := src.cpu()
			if total > prevTotal && prevTotal > 0 && busy >= prevBusy {
				r.CPU = clampPct(float64(busy-prevBusy) / float64(total-prevTotal) * 100)
			}
			prevBusy, prevTotal = busy, total
		}
		if has("mem") {
			m := src.memory()
			r.MemUsed, r.MemTotal, r.Pressure = m.Used, m.Total, m.Pressure
		}
		if has("disk") {
			r.Free = src.disk().Free
		}
		if machine != nil {
			s := machine.readSome(time.Now(), gpu, net, temp)
			r.GPU, r.NetDown, r.NetUp, r.ChipTemp = s.GPU, s.NetDown, s.NetUp, s.ChipTemp
		}
		if has("battery") {
			r.Battery = src.battery()
		}
		show(r)
		select {
		case <-ctx.Done():
			return
		case <-tick.C:
		}
	}
}

func bitmapPNG(rep objc.ID) []byte {
	dict := objc.ID(objc.GetClass("NSDictionary")).Send(nsSel("dictionary"))
	data := rep.Send(nsSel("representationUsingType:properties:"), uint64(4) /* NSBitmapImageFileTypePNG */, dict)

		return nil
	}
	// Taking the address and dereferencing keeps go vet from flagging the
	// uintptr→pointer conversion, as in nsGoString.
	ptr := *(*unsafe.Pointer)(unsafe.Pointer(&b))
	return append([]byte(nil), unsafe.Slice((*byte)(ptr), n)...)

package main

// menubar_draw_darwin.go draws a reading's two lines into the image its menu
// bar icon shows, with AppKit, as appicon_darwin.go draws app icons
// (menubar spec §三.1, §九).

import (
	"math"
	"runtime"

	"github.com/ebitengine/purego/objc"
)

// nsSize is NSSize, passed and returned by value.
type nsSize struct{ W, H float64 }

// mygo shows every menu bar image 18 points tall; the readings draw at twice
// that for Retina displays, with a point of room on each side.
const (
	readoutHeight = 18.0
	readoutScale  = 2.0
	readoutPad    = 1.0
)

// The lines' fonts, in points: a small label above a larger value, or two
// middle-sized values for the network. The weights are AppKit's
// NSFontWeightMedium and NSFontWeightSemibold.
const (
	readoutLabelSize = 7.5
	readoutValueSize = 11.5
	readoutDuoSize   = 9.0
	readoutMedium    = 0.23
	readoutSemibold  = 0.3
)

// The lines' baselines, in points above the image's bottom edge.
const (
	readoutLabelBase = 11.4
	readoutValueBase = 1.6
	readoutDuoTop    = 10.0
	readoutDuoBottom = 1.3
)

// readoutLabelAlpha is how much of the ink a label gets, to read lighter than
// its value.
const readoutLabelAlpha = 0.55

// readoutInk says how an icon is colored. A template is black with a lighter
// label, and macOS tints it for the menu bar and its highlight. An icon in
// color is drawn in the menu bar's ink, light on a dark bar and dark on a light
// one, with its value in its tone: the page's --warn and --danger on a light
// bar, --warn-text and --danger-strong of its dark theme on a dark one.
type readoutInk struct {
	template bool
	dark     bool
	tone     string
}

// rgba is a color in sRGB, each part 0–1.
type rgba struct{ r, g, b, a float64 }

func hexRGBA(c uint32) rgba {
	return rgba{float64(c>>16&0xff) / 255, float64(c>>8&0xff) / 255, float64(c&0xff) / 255, 1}
}

// colors returns the label's and the value's colors.
func (k readoutInk) colors() (label, value rgba) {
	if k.template {
		return rgba{0, 0, 0, readoutLabelAlpha}, rgba{0, 0, 0, 1}
	}
	ink := 0.0
	if k.dark {
		ink = 1
	}
	label, value = rgba{ink, ink, ink, readoutLabelAlpha}, rgba{ink, ink, ink, 1}
	switch {
	case k.tone == "warn" && k.dark:
		value = hexRGBA(0xFFC35A)
	case k.tone == "warn":
		value = hexRGBA(0xB45309)
	case k.tone == "crit" && k.dark:
		value = hexRGBA(0xF0666A)
	case k.tone == "crit":
		value = hexRGBA(0xD92D20)
	}
	return label, value
}

// readoutFonts returns the fonts of t's top and bottom lines; 0 when AppKit
// has none.
func readoutFonts(t menuBarText) (top, bottom objc.ID) {
	fonts := objc.ID(objc.GetClass("NSFont"))
	digits := func(size float64) objc.ID {
		return fonts.Send(nsSel("monospacedDigitSystemFontOfSize:weight:"), size, readoutSemibold)
	}
	if !t.Label {
		return digits(readoutDuoSize), digits(readoutDuoSize)
	}
	return fonts.Send(nsSel("systemFontOfSize:weight:"), readoutLabelSize, readoutMedium), digits(readoutValueSize)
}

// textAttributes is the attribute dictionary that draws in font and c, both
// set.
func textAttributes(font objc.ID, c rgba) objc.ID {
	color := objc.ID(objc.GetClass("NSColor")).Send(nsSel("colorWithSRGBRed:green:blue:alpha:"), c.r, c.g, c.b, c.a)
	keys := objc.ID(objc.GetClass("NSMutableArray")).Send(nsSel("array"))
	values := objc.ID(objc.GetClass("NSMutableArray")).Send(nsSel("array"))
	keys.Send(nsSel("addObject:"), nsString("NSFont")) // NSFontAttributeName
	values.Send(nsSel("addObject:"), font)
	keys.Send(nsSel("addObject:"), nsString("NSColor")) // NSForegroundColorAttributeName
	values.Send(nsSel("addObject:"), color)
	return objc.ID(objc.GetClass("NSDictionary")).Send(nsSel("dictionaryWithObjects:forKeys:"), values, keys)
}

// readoutWidth is the width in points an icon needs for t: its wider line and
// the room on each side, rounded up to a whole pixel; 0 when AppKit cannot
// say.
func readoutWidth(t menuBarText) float64 {
	if !appKitInit() {
		return 0
	}
	runtime.LockOSThread()
	defer runtime.UnlockOSThread()
	var w float64
	withPool(func() {
		top, bottom := readoutFonts(t)
		if top == 0 || bottom == 0 {
			return
		}
		for _, line := range []struct {
			s    string
			font objc.ID
		}{{t.Top, top}, {t.Bottom, bottom}} {
			if line.s == "" {
				continue
			}
			size := objc.Send[nsSize](nsString(line.s), nsSel("sizeWithAttributes:"), textAttributes(line.font, rgba{0, 0, 0, 1}))
			w = max(w, size.W)
		}
	})
	if w == 0 {
		return 0
	}
	return math.Ceil((w+2*readoutPad)*readoutScale) / readoutScale
}

// drawReadout draws t into an image w points wide and 18 tall, at twice that
// in pixels, and encodes it as PNG; nil when it cannot. Each line sits on a
// fixed baseline, so a label in another script, or a value without
// descenders, sits where every other does. It locks the calling goroutine to
// its thread for the autorelease pool and the current graphics context.
func drawReadout(t menuBarText, w float64, ink readoutInk) []byte {
	if w <= 0 || !appKitInit() {
		return nil
	}
	runtime.LockOSThread()
	defer runtime.UnlockOSThread()
	var out []byte
	withPool(func() {
		topFont, bottomFont := readoutFonts(t)
		if topFont == 0 || bottomFont == 0 {
			return
		}
		rep := objc.ID(objc.GetClass("NSBitmapImageRep")).Send(nsSel("alloc")).Send(
			nsSel("initWithBitmapDataPlanes:pixelsWide:pixelsHigh:bitsPerSample:samplesPerPixel:hasAlpha:isPlanar:colorSpaceName:bytesPerRow:bitsPerPixel:"),
			uintptr(0), int(math.Round(w*readoutScale)), int(readoutHeight*readoutScale), 8, 4, true, false, nsString("NSDeviceRGBColorSpace"), 0, 0)
		if rep == 0 {
			return
		}
		defer rep.Send(nsSel("release"))
		rep.Send(nsSel("setSize:"), nsSize{w, readoutHeight}) // draw in points
		ctx := objc.ID(objc.GetClass("NSGraphicsContext")).Send(nsSel("graphicsContextWithBitmapImageRep:"), rep)
		if ctx == 0 {
			return
		}
		gc := objc.ID(objc.GetClass("NSGraphicsContext"))
		gc.Send(nsSel("saveGraphicsState"))
		gc.Send(nsSel("setCurrentContext:"), ctx)
		label, value := ink.colors()
		topColor, topBase, bottomBase := value, readoutDuoTop, readoutDuoBottom
		if t.Label {
			topColor, topBase, bottomBase = label, readoutLabelBase, readoutValueBase
		}
		line := func(s string, font objc.ID, c rgba, base float64) {
			if s == "" {
				return
			}
			// Without NSStringDrawingUsesLineFragmentOrigin, the rectangle's
			// origin is the line's baseline.
			nsString(s).Send(nsSel("drawWithRect:options:attributes:"),
				nsRect{readoutPad, base, w, readoutHeight}, uint64(0), textAttributes(font, c))
		}
		line(t.Top, topFont, topColor, topBase)
		line(t.Bottom, bottomFont, value, bottomBase)
		gc.Send(nsSel("restoreGraphicsState"))
		out = bitmapPNG(rep)
	})
	return out
}

// realMenuBarSource wires the readings to the home page's reads
// (status_darwin.go, fs_darwin.go, machine_darwin.go) and the battery's charge.
func realMenuBarSource() menuBarSource {
	return menuBarSource{
		cpu:    cpuBusyTotal,
		memory: readMemoryStatus,
		disk:   diskStat,
		machine: func() menuBarMachine {
			r, _ := newMachineReader().(*machineReader)
			if r == nil { // a nil *machineReader would make a non-nil interface
				return nil
			}
			return r
		},
		battery: menuBarBatteryLevel,
	}

// menuBarBatteryLevel is the battery's charge in percent, read from
// AppleSmartBattery as the system's own battery item reads it, without
// system_profiler (spec §六); -1 without a battery or when it cannot be read.
// On Apple silicon CurrentCapacity is a percentage of MaxCapacity, 100; on
// Intel both are mAh: the ratio is the charge either way.
func menuBarBatteryLevel() int {
	if !iokitInit() {
		return -1
	}
	battery := ioFirst("AppleSmartBattery")
	if battery == 0 {
		return -1
	}
	defer ioObjectRelease(battery)
	cur, ok := ioPropInt(battery, "CurrentCapacity")
	full, fullOK := ioPropInt(battery, "MaxCapacity")
	if !ok || !fullOK || cur < 0 || full <= 0 {
		return -1
	}
	return int(math.Min(100, math.Round(float64(cur)*100/float64(full))))
}

// menuBarHasBattery tells whether this Mac has a battery, asked once.
var menuBarHasBattery = sync.OnceValue(func() bool {
	if !iokitInit() {
		return false
	}
	battery := ioFirst("AppleSmartBattery")
	if battery == 0 {
		return false
	}
	ioObjectRelease(battery)
	return true
})

// width is the room item's icon takes for t: its widest usual text's, or t's
// when that is wider, as for a disk with a thousand gigabytes free.

	return max(m.widths[item], readoutWidth(t))

// draw shows reading r, drawing again only the icons whose text changed.
func (m *menuBarController) draw(r menuBarReading) {
	m.last = r
	for item, tray := range m.trays {
		text := menuBarTextFor(item, r, nativeText)
		if prev, ok := m.drawn[item]; ok && prev == text {
			continue
		}
		m.paint(item, tray, text)
	}

// paint draws t into item's icon: a template, or in the menu bar's ink when it
// has a tone.

	ink := readoutInk{template: t.Tone == "", tone: t.Tone}
	if !ink.template {
		ink.dark = tray.Dark()
	}
	png := drawReadout(t, m.width(item, t), ink)

		return
	}

		log.Println("menubar:", err)
		return
	}
	m.drawn[item] = t
}

// icon in color needs it: macOS tints the templates itself.

		if tray := m.trays[item]; tray != nil {
			m.paint(item, tray, t)
		}
	}
}

		return
	}

		tray.SetToolTip(nativeText("menubar.tip."+item, nil))

	}

// growthMenuItem is one line of the menu bar menu. A zero item is a separator.
type growthMenuItem struct {

	action   string // "focus", "open", "measure", "off", "settings" or "quit"

// growthMenuModel lists the menu while monitoring is on (spec §六):
//   - the three owners that grew most in seven days, ignored ones left out;
//   - then the lines of growthMenuCommands.
func growthMenuModel(apps []GrowthApp, running bool, text func(string, map[string]string) string) []growthMenuItem {
	var top []GrowthApp
	for _, a := range apps {
		if a.Week != nil && a.Week.Bytes > 0 && !a.Ignored {
			top = append(top, a)
		}
	}
	slices.SortFunc(top, func(x, y GrowthApp) int {
		return cmp.Or(cmp.Compare(y.Week.Bytes, x.Week.Bytes), strings.Compare(x.Key, y.Key))
	})
	var items []growthMenuItem
	for _, a := range top[:min(3, len(top))] {
		key := "growth.tray.item"
		if a.Week.AtLeast {
			key = "growth.tray.itemAtLeast"
		}
		items = append(items, growthMenuItem{label: text(key, map[string]string{"name": a.Name, "size": growthSize(a.Week.Bytes)}), action: "focus", key: a.Key})
	}
	if len(items) == 0 {
		items = append(items, growthMenuItem{label: text("growth.tray.none", nil), disabled: true})
	}
	return append(append(items, growthMenuItem{}), growthMenuCommands(running, text)...)
}

// growthMenuCommands lists the lines of the growth menu that act: open, measure
// now (or that it is measuring) and turning monitoring off, then
// menuBarMenuTail. It is also the menu the icon starts with, before the records

func growthMenuCommands(running bool, text func(string, map[string]string) string) []growthMenuItem {

// growthTrayMenu turns the model into a mygo menu whose lines call act. Tests
// give it their own act to see which line does what.
func growthTrayMenu(items []growthMenuItem, act func(growthMenuItem)) *mygo.Menu {
	var out []*mygo.MenuItem
	for _, it := range items {
		if it == (growthMenuItem{}) {
			out = append(out, mygo.Separator())
			continue
		}
		out = append(out, &mygo.MenuItem{Label: it.label, Disabled: it.disabled, Click: func(*mygo.MenuItem, *mygo.Window) { act(it) }})
	}
	return mygo.NewMenu(out)
}

// growthIconPNG draws the menu bar icon: a drive with an arrow rising above
// it. It is a template image, black on transparent, 32×32 pixels for 16
// points at 2×; macOS tints it for light and dark menu bars.
func growthIconPNG() []byte {
	img := image.NewNRGBA(image.Rect(0, 0, 32, 32))
	ink := color.NRGBA{A: 255}
	fill := func(x0, y0, x1, y1 int) {
		for y := y0; y < y1; y++ {
			for x := x0; x < x1; x++ {
				img.SetNRGBA(x, y, ink)
			}
		}
	}
	// drive: a 2 px outline from (4,19) to (28,29), with a light at the right
	fill(4, 19, 28, 21)
	fill(4, 27, 28, 29)
	fill(4, 19, 6, 29)
	fill(26, 19, 28, 29)
	fill(21, 23, 24, 25)
	// arrow: a shaft and a head pointing up from (16,3)
	fill(15, 3, 17, 16)
	for i := 0; i <= 6; i++ {
		fill(15-i, 3+i, 17-i, 5+i)
		fill(15+i, 3+i, 17+i, 5+i)
	}
	var buf bytes.Buffer
	_ = png.Encode(&buf, img)
	return buf.Bytes()
}

// menuBarHolds are the panels a quit under way keeps open (spec §四.5).
var menuBarHolds = struct {
	sync.Mutex
	held map[*mygo.Window]bool
}{held: map[*mygo.Window]bool{}}

// menuBarHeld tells whether a quit under way keeps w open.
func menuBarHeld(w *mygo.Window) bool {
	menuBarHolds.Lock()
	defer menuBarHolds.Unlock()
	return menuBarHolds.held[w]
}

// menuBarRelease lets w close again.
func menuBarRelease(w *mygo.Window) {
	menuBarHolds.Lock()
	delete(menuBarHolds.held, w)
	menuBarHolds.Unlock()
}

// MenuBarHold keeps the panel that calls it open while hold is true: a quit is
// under way, and its result must show (spec §四.5). Clicking elsewhere, or on
// the reading, leaves the panel open until the quit is done.
func (Cleaner) MenuBarHold(ctx context.Context, hold bool) {
	w := mygo.CallerWindow(ctx)
	if w == nil {
		return
	}
	if !hold {
		menuBarRelease(w)
		return
	}
	menuBarHolds.Lock()
	menuBarHolds.held[w] = true
	menuBarHolds.Unlock()
}

// t names in the main window, making the window again if it was closed
// (spec §四.6).
func (Cleaner) MenuBarOpen(ctx context.Context, t MenuBarTarget) {
	if w := mygo.CallerWindow(ctx); w != nil && w.IsFlyout() {
		menuBarRelease(w)
		w.Destroy()
	}
	menuBarGo(t)
}

/** 一句话诊断（设计 §四的表，Cleanzo 的特色）：读数还没到时为 null，面板画一条占位。 */
export function diagnosis(item: PanelItem, d: DiagInput, t: T): PanelDiag | null {
  const s = d.s;
  const m = s?.machine ?? null;
  switch (item) {
    case "cpu": {
      const top = d.proc ? sortRows(d.proc.rows, "cpu")[0] : undefined;
      if (!top) return null;
      const vars = { name: top.name, pct: est(fmtPct(top.cpu), top.estimated) };
      return busy(d.cpuHist) ? { tone: "warn", text: t("process.diag.cpu", vars) } : { tone: "ok", text: t("menubar.diag.cpuIdle", vars) };
    }
    case "mem": {
      const top = d.proc ? sortRows(d.proc.rows, "mem")[0] : undefined;
      if (!s || !top) return null;
      const vars = { name: top.name, size: est(fmtMem(top.memory), top.estimated) };
      const swap = s.memory.swapTotal >= STATUS_ALERT.swapMentionGB * GiB
        ? ` ${t("status.alert.swapLine", { size: fmtMem(s.memory.swapTotal) })}`
        : "";
      const p = s.memory.pressure;
      if (p === 2 || p === 4) return { tone: p === 4 ? "crit" : "warn", text: t("process.diag.mem", vars) + swap };
      return { tone: "ok", text: t("menubar.diag.memOk", vars) + swap };
    }
    case "gpu":
      if (!m || m.gpu < 0) return null;
      return busy(d.gpuHist) ? { tone: "warn", text: t("menubar.diag.gpuBusy") } : { tone: "ok", text: t("menubar.diag.gpuIdle") };
    case "net":
      if (!m) return null;
      return {
        tone: "ok",
        text: t(m.netKind === "wifi" ? "menubar.diag.netWifi" : m.netKind === "ethernet" ? "menubar.diag.netEthernet" : "menubar.diag.netNone"),
      };
    case "disk": {
      if (!s || !(s.disk.free > 0)) return null;
      const low = s.disk.free < STATUS_ALERT.diskFreeWarnGB * GiB;
      let text = t(low ? "status.alert.diskLow" : "menubar.diag.diskOk", { size: fmtMem(s.disk.free) });
      const a = growthHint(d.growth, []);
      if (a) {
        const size = a.atLeast ? t("growth.atLeast", { size: human(a.bytes) }) : human(a.bytes);
        const alert = t(a.window === "day" ? "status.alert.growthDay" : "status.alert.growthWeek", { app: a.name, days: a.days, size });
        text += ` ${t("menubar.diag.growth", { alert })}`;
      }
      return { tone: low || a ? "warn" : "ok", text };
    }
    case "temp": {
      if (!m || m.thermal < 0) return null;
      const n = Math.min(m.thermal, 3);
      return { tone: n === 0 ? "ok" : n === 1 ? "warn" : "crit", text: t(`menubar.diag.thermal${n}` as DictKey) };
    }
    case "battery": {
      const b = s?.battery;
      if (!b) return null;
      const state = b.full
        ? t("status.battery.full")
        : b.charging
          ? t("status.battery.charging", { pct: `${b.percent}%` })
          : b.plugged ? t("status.battery.plugged") : t("status.battery.onBattery");
      const cond = b.condition.trim().toLowerCase();
      const service = cond !== "" && cond !== "good" && cond !== "normal";
      return service ? { tone: "warn", text: `${state} · ${t("status.battery.service")}` } : { tone: "ok", text: state };
    }
  }
}

      if (b.plugged && b.adapterWatts > 0) add({ key: "adapter", label: t("status.battery.adapter"), value: `${b.adapterWatts} W` });
      break;
    }
  }
  return rows;
}

/** 内存条三段（App、联动、被压缩）各占总量的百分比；总量读不到时为 null。 */
export function memShares(m: MemoryStatus): { app: number; wired: number; compressed: number } | null {
  if (!(m.total > 0)) return null;
  const pct = (n: number) => Math.max(0, Math.min(100, (n / m.total) * 100));
  return { app: pct(m.app), wired: pct(m.wired), compressed: pct(m.compressed) };
}

/** 列表：按 CPU 或内存排的前 5 行（排法同「进程」页）；frozen 时沿用上一轮的行和顺序，只换数字。 */
export function topRows(sample: ProcessSample, by: "cpu" | "mem", prev: readonly ProcessRow[], frozen: boolean): ProcessRow[] {
  return frozen && prev.length > 0 ? refreshFrozen(prev, sample) : sortRows(sample.rows, by).slice(0, PANEL_TOP);
}

/** 磁盘面板的「涨得最快」：增长监控开着时，近 7 天涨了、没被忽略的 App，最多 5 个，涨得多的在前。 */
export function growthTop(g: GrowthState | null): GrowthApp[] {
  if (!g || !g.supported || !g.config.enabled) return [];
  return g.apps
    .filter((a) => !a.ignored && (a.week?.bytes ?? 0) > 0)
    .sort((a, b) => b.week!.bytes - a.week!.bytes || a.key.localeCompare(b.key))
    .slice(0, PANEL_TOP);
}

/** 一行的退出流程（设计 §四.5）：退出、确认、正在退出，没退掉时还没退出、确认强制、正在强制，最后已退出或失败。 */
export type QuitStep = "idle" | "confirm" | "quitting" | "stuck" | "forceConfirm" | "forcing" | "done" | "failed";

/** 列表各行的退出状态；gone 是「已退出」后离开过列表的行，同一个 App 再出现时恢复成可退出。 */
export interface QuitBook {
  steps: ReadonlyMap<string, QuitStep>;
  gone: ReadonlySet<string>;
}

export const emptyBook = (): QuitBook => ({ steps: new Map(), gone: new Set() });

/** 「确认退出」「确认强制退出」没点第二下，多久退回。 */
export const QUIT_CONFIRM_MS = 3000;

export function withStep(b: QuitBook, key: string, step: QuitStep): QuitBook {
  return { ...b, steps: new Map(b.steps).set(key, step) };
}

/** 有一行在等第二下。 */
export function confirming(b: QuitBook): boolean {
  return [...b.steps.values()].some((s) => s === "confirm" || s === "forceConfirm");
}

/** 正在退出、正在强制退出：面板这时不自动关上（设计 §四.5）。 */
export function quitPending(b: QuitBook): boolean {
  return [...b.steps.values()].some((s) => s === "quitting" || s === "forcing");
}

/** 列表不重排：指针在列表里，或有一行在确认、在退出（设计 §四.5）。 */
export function listFrozen(hover: boolean, b: QuitBook): boolean {
  return hover || confirming(b) || quitPending(b);
}

/** 确认没点第二下：「确认退出」退回原样，「确认强制退出」退回「还没退出」；没有在确认的行时原样返回。 */
export function revertConfirms(b: QuitBook): QuitBook {
  if (!confirming(b)) return b;
  const steps = new Map<string, QuitStep>();
  for (const [k, v] of b.steps) {
    if (v === "forceConfirm") steps.set(k, "stuck");
    else if (v !== "confirm") steps.set(k, v);
  }
  return { ...b, steps };
}

/**
 * 每次进程读数后对账（同「进程」页的 syncQuitRows）：「已退出」的行离开列表后记下，同一个 App 再出现时恢复成可退出；
 * 「还没退出」「退出失败」的 App 不在了就忘掉。没变时原样返回。
 */
export function syncBook(b: QuitBook, rows: readonly ProcessRow[]): QuitBook {
  if (b.steps.size === 0 && b.gone.size === 0) return b;
  const present = new Set(rows.map((r) => r.key));
  const steps = new Map(b.steps);
  const gone = new Set(b.gone);
  for (const [k, v] of b.steps) {
    if (v === "done") {
      if (!present.has(k)) gone.add(k);
      else if (b.gone.has(k)) {
        steps.delete(k);
        gone.delete(k);
      }
    } else if ((v === "stuck" || v === "failed") && !present.has(k)) {
      steps.delete(k);
    }
  }
  const same = steps.size === b.steps.size && gone.size === b.gone.size && [...gone].every((k) => b.gone.has(k));
  return same ? b : { steps, gone };
}

  const by = item === "mem" ? "mem" : "cpu";

  const [gpuHist, setGpuHist] = React.useState<number[]>([]);
  const [proc, setProc] = React.useState<ProcessSample | null>(null);

  const [sys, setSys] = React.useState<SystemInfo | null>(null);
  const [growth, setGrowth] = React.useState<GrowthState | null>(null);

  const [hover, setHover] = React.useState(false);
  const [book, setBook] = React.useState<QuitBook>(emptyBook);
  const shownRef = React.useRef<ProcessRow[]>([]);

    let live = true;
    const ch = new Channel<StatusSample>();
    setFailed(false);

      try {
        const done = panelApi.watch(item, ch);
        for await (const v of ch) {
          if (!live) continue;
          setS(v);
          const p = chartPoint(item, v);
          if (p !== null) setHist((h) => trimSpark(h, p));
          const gpu = v.machine?.gpu ?? -1;

        await done;
      } catch {
        if (live) setFailed(true);
      }
    })();

        const done = panelApi.watchProcesses(ch);
        for await (const v of ch) {
          if (!live) continue;
          setProc(v);
          setCpuHist((h) => pushCpu(h, v.cpu));
          setBook((b) => syncBook(b, v.rows));
        }
        await done;
      } catch { /* 读不到进程：诊断和列表留着占位 */ }

    return () => { live = false; ch.close(); };

  const details = detailRows(item, s, info, t);

          <i style={{ transform: seg(shares.app + shares.wired, shares.compressed), background: "var(--seg-compressed)" }} />
        </div>
      )}
      {details.length > 0 && (
        <ul className="mb-rows">
          {details.map((r) => (
            <li key={r.key}>
              <span className="k">{r.dot && <i className="dot" style={{ background: r.dot }} />}{r.label}</span>

              <b>{r.value}</b>

                by={by}
                step={stepOf(r.key)}

                onQuit={() => void quit(r)}
                onForce={() => void force(r)}

            : Array.from({ length: 3 }, (_, i) => <div key={i} className="mb-skel-row" aria-hidden="true" />)}
        </section>
      )}

          {PANEL[item].links.map((l) => (

          ))}
        </span>
        <span className="mb-every">{t("menubar.panel.every")}</span>

    </main>
  );

/** 勾上或取消一项后的整份列表，按固定顺序；不认识的名字去掉。 */
export function toggleMenuBarItem(items: readonly string[], item: string, on: boolean): string[] {
