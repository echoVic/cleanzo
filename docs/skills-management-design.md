# Cleanzo 新模块设计 · 技能管理（Agent Skills）

> 版本：v0.1 ｜ 日期：2026-10-18
> 代码：`skills.go`、`skills_test.go`、`src/react/skills/`、`tests/skills-react.test.ts`
> 定位一句话：**把散在各个 AI 工具目录里的技能汇总成一份清单，用对话记录里的真实调用说明哪些在用、哪些久未使用，标出重复、分叉和失效的副本；清理只进废纸篓，合并只做内容完全相同的副本。**

---

## 一、为什么做成「管理」而不是「专清」

技能目录加起来通常只有几十 MB（本机 4 个主要目录合计约 46 MB），按占用空间算没有清理价值。真正的问题是：

- **重复与分叉**：同一个技能在 `~/.agents`、`~/.claude`、`~/.codex`、`~/.gemini` 等目录各存一份实体副本（本机 42 个技能有实体重复），改了一份另一份没跟上就会分叉，agent 每次加载的技能清单也会变长。
- **不知道哪些还在用**：装了上百个技能，没有地方能看「最近谁被调用过、谁一直没用」。
- **软链关系看不见**：`~/.claude/skills` 里大量软链指向 `~/.agents/skills`，直接删源目录会让别的工具留下失效链接。

所以页面放在侧栏「AI 工具」分组下，主要能力是**清单 + 调用证据 + 问题标记 + 安全合并/移除**，不和垃圾清理混在一起，也不重复 CC Switch 那类安装、启用开关的功能。

---

## 二、扫描范围

| 工具 | 技能目录 | 调用记录来源 |
|---|---|---|
| 共享 | `~/.agents/skills` | 被 Codex、OpenCode 读取 |
| Claude Code | `~/.claude/skills` | `~/.claude/projects/**/*.jsonl` |
| Codex | `~/.codex/skills` | `~/.codex/sessions/**/*.jsonl`、`~/.codex/archived_sessions/*.jsonl.zst` |
| OpenCode | `~/.config/opencode/skills` | `~/.local/share/opencode/opencode.db`（系统 sqlite3，只读） |
| Gemini CLI / Grok / Hermes / Pi | 各自 skills 目录 | 无可读记录 → 显示「无数据」 |

隐藏条目（`.system`、`.DS_Store` 等）和散落的普通文件不算技能。

---

## 三、调用记录怎么认

**核心原则：只认确定是一次调用的记录，拿不到就显示「无数据」，绝不显示成「没用过」。**

| 来源 | 认什么 | 不认什么 |
|---|---|---|
| Claude Code | assistant 消息里 `tool_use` 名为 `Skill` 的调用（按 tool_use id 去重，续接会话复制过来的同一次调用只算一次）；用户输入的 `<command-name>` 斜杠命令 | 正文里恰好出现 `"name":"Skill"` 字样的文本 |
| Codex | `response_item` 里 `function_call` / `custom_tool_call` / `local_shell_call` 参数中、**路径落在已知技能目录下**的 `SKILL.md` 读取（按 call_id 去重） | 提示词里注入的技能清单；插件缓存、memories 下的同名 SKILL.md；工具输出 |
| OpenCode | `part` 表里 `tool = "skill"` 的调用，以及工具输入里落在已知技能目录下的 SKILL.md 读取 | — |

Codex 的 `archived_sessions` 是 zstd 压缩的，用纯 Go 的 `klauspost/compress/zstd` 解码，不依赖系统是否装了 `zstd` 命令。本机读上压缩归档后，Codex 记录从 9 天延伸到约 397 天。

## 四、「久未使用」的判定

每个来源报告**记录能回溯到的最早时间**（最旧的那份记录文件的修改时间，OpenCode 取库里最早的 `time_created`）。一个技能被判为久未使用，需要同时满足：

1. **可观测**：至少有一个能读到记录的工具会加载它（`~/.agents` 里的技能由 Codex、OpenCode 观测；`~/.claude` 由 Claude Code 和 OpenCode 观测）。
2. **窗口取最短**：被多个工具观测时，取各工具记录起点里**最晚**的那个，即所有工具都覆盖到的那段时间。
3. **装在窗口之前**：技能条目的修改时间早于窗口起点，避免刚装上的技能被误判。
4. **窗口至少 14 天**（`skillIdleWindow`），记录太短不下结论。
5. **窗口内调用 0 次**。

UI 文案对应：
- 有调用：「N 天前 · M 次」
- 判定为久未使用：「N 天内未调用」+ 红色「久未使用」标签
- 可观测但不满足上面条件：「N 天内未调用 · 待观察」
- 不可观测：「无数据」

## 五、问题标记

| 标记 | 含义 |
|---|---|
| 链接失效 | 软链指向的目标不存在或不是目录 |
| 缺少 SKILL.md | 是目录，但里面没有 SKILL.md |
| 重复副本 | 同名技能有 ≥2 份实体目录，内容哈希完全相同 |
| 副本不一致 | 同名技能有 ≥2 份实体目录，内容不同（或超过 64 MB 无法比较） |

内容哈希覆盖相对路径、文件内容和内部软链目标，不跟随软链，跳过 `.DS_Store`。

## 六、操作与安全约束

### 移到废纸篓（`TrashSkills`）
- 默认不勾选任何技能。
- 只接受**已知技能目录的直接子项**；隐藏条目、技能目录本身、目录外路径一律拒绝（`not-a-skill`），并复用 `safeToClean` 的主目录保护。
- 软链只移软链本身，不动目标。
- 实体目录如果还被别的技能目录里的软链指着，**必须连同这些软链一起移走**，否则拒绝（`linked`），避免留下失效链接；软链先移、目录后移。
- 正在被进程打开的目录跳过（`in-use`），沿用 lsof 探测。
- 确认弹窗列出将移走的技能；如果有指向这些目录、但属于其他技能名的软链，单独列出提示。

### 换成软链（`LinkSkillCopy`）
- 只处理**同名、内容哈希完全相同、都是实体目录、分属不同工具目录**的副本，目标优先是 `~/.agents` 里那份。
- 被其他软链引用的副本不提供合并。
- 步骤：先在旁边建好临时软链 → 原目录移入废纸篓 → 临时软链改名到原位置。原目录可从废纸篓找回。
- 内容不同的副本拒绝合并（`diverged`），UI 提示用户自行比对。

## 七、验证记录

- Go 单测（临时 HOME，不碰真实文件）：清单与问题标记、三种来源的调用统计、zstd 归档读取、久未使用的各个边界（新装、窗口不足 14 天）、废纸篓的各类拒绝与连带移除、换成软链（成功、分叉拒绝、改名拒绝、重复合并拒绝）。
- 前端单测：筛选、搜索、排序、天数换算、移除计划（含跨名字软链）、可合并副本判断。
- 真机 GUI（`bun run dev`，测试技能用完即删）：扫描与标记、换成软链后文件系统核对、分叉不提供合并、三类移除（被软链引用的目录、失效软链、跨名字软链只移软链）、久未使用与无数据筛选、浅色与深色模式。

## 八、已知限制

- Gemini CLI、Grok、Hermes、Pi 没有可读的调用记录，只能显示「无数据」。
- Claude Code 默认只保留约 30 天会话，它观测的技能「久未使用」窗口受此限制。
- 超过 64 MB 的技能目录不计算内容哈希，不会被判为「重复」，也不提供合并。
- 插件自带的技能（如 `superpowers:*`）不在用户技能目录里，不列出。
